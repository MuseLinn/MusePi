# 少样本泄漏示例

从仓库级清理及评审轮次中蒸馏。用来识别主导原则，不是当文本模板。本文件故意引用
泄漏措辞做校准——[recall batteries](recall-batteries.md) 会排除本 skill 目录，且这里的
措辞不是别处的许可证。

## 死引用

### 有归属者的决策序号

**泄漏：** "Slash 输入按可见目录解析（决策 21）。"

**修正：** "Slash 输入按可见目录解析——纯文本引用决策，归属
`docs/skills.md` 的运行时说明。"（或按实际归属文档路径引用）

序号在 HEAD 上无法解析；决策的名字和归属路径可以。每个文件至少点名一次归属路径，
后续提及可用可搜索的名字。

### 无归属者的决策序号

**泄漏：** "注册表拒绝重名（决策 7：名字是扁平的，无命名空间）。"

**修正：** "注册表拒绝重名；名字是扁平的，无命名空间。"

没有已提交产物归属"决策 7"，所以引用被删——但事实分句（扁平名字）改写成独立成立，
没有跟着删。

### 审计条目码

**泄漏：** "渲染是纯函数：同快照同字符串（审计 R3）。"

**修正：** "渲染是纯函数：同快照同字符串。"

仓库里没有审计文档；`(审计 R3)` 是零命题的会话速记。

### 未提交草稿的节号

**泄漏：** "分层按设计稿（v2 §3.2）：`src/core/` 是纯核心。"

**修正：** "分层：`src/core/` 是纯核心。"

没人提交的草稿的 `§N` 无法解析。对照："转义按 RFC 9110 §10.1.5" 保留——外部标准
按设计在仓库外可解析，自有 §-编号的已提交文档也可以按节引用。

### 计划阶段标签

**泄漏：** "`src/client/` 是外壳（T4）；P-I 迁移拥有适配器。"

**修正：** "`src/client/` 是外壳；适配器在 `src/client/adapters/`。"

阶段标签索引的是一份从未落地的计划。用阶段产出替换标签。

## PR/栈视角

### 持久文案里的栈位置

**泄漏：** "未来的远程后端实现该接口（沙箱后端是这个栈里后面的 PR）。"

**修正：** "远程后端可以不改渲染层就实现该接口。"

现状文看不到栈。保留扩展点契约；未竟工作的家是 PR 本身、`TODO` 或 issue。

### README 里的 "This PR"

**泄漏：** "This PR adds cursor-based pagination to the session list."

**修正：** "The session list paginates by cursor."

README 活得比每个 PR 都长；把机制写成现状事实。

## 变更叙述与版本戳

### 带 PR 号的战争故事

**泄漏：** "颜色以前来自 `--widget-*` token，没人定义所以总是渲染兜底；别名 token
修好了这个（PR #88）。"

**修正：** "颜色来自别名 token；未定义 token 渲染兜底。"

两个活事实都活下来——当前机制和常驻失败行为——用现在时改写。bug 的传记属于 PR 和
CHANGELOG。

### 删除叙述

**泄漏：** "`probe` 字段随删除 cut 没了；badge 现在走通用投影对。"

**修正：** "Badge 使用通用投影对。"

没见过 `probe` 的读者从它的缺席中学不到任何东西。"现在"对比一个被删的过去就是
版本戳。

### 已修复回归 → 现在时反事实

**泄漏：** "这以前会双重编码多字节标签。"

**修正：** "没有字节长度保护，多字节标签会双重编码。"

回归钉以现在时反事实存活，点名保护者；"以前"把它钉在仓库考古上。

### 指示性版本戳

**泄漏：** "批渲染这个 cut 是同步的；异步路径是 roadmap 工作。"

**修正：** "批渲染是同步的。"（推迟活在调用点的 `TODO(widget-batch):` 里）

"这个 cut"/"v1"/"今天"一合并就过期。历史阶段名在 CHANGELOG 条目里（"首个 cut 发布
了 X"）是安全的；指示词形式永远不是。

## 评审对白

### 评审结论当正文

**泄漏：** "评审中否了：缓存解析后的 spec。我们每次调用都重新解析。"

**修正：** "**缓存解析后的 spec。** 否决：spec 依赖每次调用的 cwd，按请求做缓存键
会喂陈旧根目录。"

把存活的决定和理由写成普通事实；评审者和轮次不是理由的一部分。

### 草稿序号

**泄漏：** "本 note 的 v5 起，loader 也校验 manifest。"

**修正：** "Loader 校验 manifest。"

现状文写已落地状态；自己的修订历史在 git 里。

## 向评审者自辩

### 为一次转换辩护

**泄漏：** "这个转换是安全的——SDK 构造了对象，它只是没把可选字段声明得够严。"

**修正：** "SDK 构造该对象时每个可选字段都已填充；声明的类型比运行时保证更松。"

写出维护者不能破坏的不变量。"它只是…"是在回答 HEAD 上没人提出的反对意见。不变量
代码里可见就直接删注释。

### 诉诸评审权威

**泄漏：** "这是对的，因为评审者确认了包装顺序。"

**修正：**（删除；包装顺序已写在函数的 `@returns` 里。）

正确性论断引用不变量或测试，从不引用人。

## 复述与推导

### 控制流叙述

**泄漏：** "先归一化标签，再截断，再换行。"

**修正：**（删除。）

注释下面三行代码说的就是同一件事。

### 测试走查

**泄漏：** "这个测试创建一个会话，发两条消息，等第二条回复，然后断言日志有 4 条。"

**修正：** "两次往返必须恰好产生 4 条日志——投影去重了共享前缀。"

只留非显然的断言理由；走查只是复述测试体。

## 含糊与计划残留

### 无标记的推迟

**泄漏：** "暂时提前渲染大概没问题。"

**修正：**（删除；推迟已有 `TODO(widget-batch):` 标记。）

没有归属者的含糊是计划残留。没有标记就写一个（`TODO(name): 按动画帧合并`）而不是
留着含糊。

### 模糊的量级

**泄漏：** "64 KiB 缓冲对大多数情况应该够了。"

**修正：** "64 KiB 装得下观测到的最大帧（48 KiB）且有富余；更大的帧在 `decode`
里大声失败。"

用实际边界和超界失败行为替换含糊。

## 写作语言残留

**泄漏：** "The renderer runs on the client 端; see the 设计稿 for spacing.
---- 私有 ----"

**修正：** "The renderer runs on the client side; spacing follows the Figma
frame `widget-badges`."

工作语言碎片和会话分隔符是转写残留。Figma 框名保留：按设计在仓库外可解析的外部
来源。

## 保留（keeps）

### issue 引用在任何面上都持久

**保留：** "该上限作用于完整渲染值（含包装）（issue #1470 owns the follow-up）。"

issue 在 HEAD 上从任何面都可解析，`#N owns the follow-up` 是 README 里推迟工作的
合法家。CHANGELOG 额外允许引**已合并的 PR** 作佐证。

### 死点名不是"点了归属者"

**删除：** "Badge renderer over the widget seam（see the widget-rendering RFC）。"

检验是可解析性，不是形式：没有已提交文件回应 "widget-rendering RFC"，指针就是死
的。有已提交归属者就改指它，否则删。

### 抑制理由

**保留（修正后）：** `// biome-ignore lint/style/useConst -- 单元素字面量保证 index 0。`

理由分句是必需文案。理由说错时（原文说"上面的循环保护证明存在帧"，而根本没有
循环）修理由，绝不删。

### 实测边界

**保留：** "深度上限（实测：512 层嵌套 ≈ 0.15s 同步；4096 会卡死循环）。"

实测把常量钉住，防止无知重调；"实测"是区分数据与猜测的来源词。

### 运行时新旧不是变更历史

**保留：** "旧连接排空后新连接才接受。"

这里"旧""新"命名交接中的两个活运行时对象，不是仓库状态。变更叙述禁令针对仓库
历史，不是生命周期词汇。

## 过度修正陷阱

每个陷阱都在最初清理中实际发生并被评审抓住。删之前先列段落命题。

### 把义务改成背书

**原文：** "这些直接注册是待迁移到 slot 的例外。"

**过度修正：** "这些直接注册是获认可的例外。"

**正确：** "这些直接注册是待迁移到 slot 的例外。"

"待迁移"是义务；"获认可"祝福了现状。修剪在缩短句子的同时颠倒了情态。

### 把假设说成已发布功能

**原文：** "未来的 IPC 外壳子类化 executor 并覆写 `spawn`。"

**过度修正：** "IPC 外壳子类化 executor 并覆写 `spawn`。"

**正确：** "假设的 IPC 外壳——目前不存在——会子类化 executor 并覆写 `spawn`。"

只删未来标记会把设计示例变成"该类已发布"的断言。明确标出假设，而不是只去掉
未来时。

### 连真事实一起删

**原文：** "门禁通知叙述了检查顺序；通知文本也是 `verify-doc-typecheck` 编译的对象。"

**过度修正：**（整句当叙述删掉。）

**正确：** "通知文本是 `bun check` 会编译的对象。"（按实际归属调整）

半句是叙述，另一半是承载耦合。共享一行的命题要按分句删，不是按句删。

### 保留数字却丢了来源

**原文：** "4 MiB 上限是实测的：最大的生成 `py-types` 模块是 3.1 MiB。"

**过度修正：** "上限是 4 MiB；最大的生成 `py-types` 模块是 3.1 MiB。"

**正确：** 保留"实测"。

没有"实测"，3.1 MiB 读起来像定义而不是观测，没人会在提高上限前重新测量。
