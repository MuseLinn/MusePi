# 清理思维链泄漏

把视角停留在写作会话、而不是仓库现状的文案改成当前可验证的事实。先按 `skill://musepi-prose-standard` 列出命题；有事实的句子改写，没有事实的转写删除。文档归属与双语验证遵循 `.agents/rules/documentation.md`。

## 判定

只读仓库现状和 git 历史的读者应能解开每个引用、验证每个论断。以下文案需要清理：

1. **死设计引用**：决策/审计编号、未提交草稿章节、阶段标签、方案台账。引用已提交归属者，或删除引用并让事实独立成立。
2. **PR 与评审视角**：本 PR、上一个 commit、评审者意见、轮次归属、向评审者自辩。改写为代码安全所依赖的不变量或当前行为。
3. **变更叙述**：以前、旧版、这版、今天等与过去比较的描述；改成当前状态。运行期“旧连接/新连接”等对象生命周期不属于此类。
4. **推导转写**：控制流复述、测试走查、显然分支证明。只留非显然契约。
5. **含糊推迟**：大概够用、应该可行、无归属暂缓。写成实际边界或带归属的 `TODO`/`FIXME`。
6. **工作语言残留**：无意义的中英碎片和内部分隔标记；翻译或删除。

保留可解析的 issue/TODO、changelog 和 postmortem 的 PR 佐证、lint/coverage 抑制理由、现在时反事实回归钉、实测边界、外部标准章节，以及已提交文档的内部章节引用。

## 工作流

1. 从用户请求、引用文件和当前任务确定范围，不默认扩展到全仓；只有范围会改变修改文件且无法判断时才澄清。
2. 先只读审计：运行 `references/recall-batteries.md` 的探针，并通读范围内最密集的文案。探针只负责召回，语义判断决定取舍。
3. 按归属修改：生成物改生成源，i18n 同步双语，模型可见文案带 snapshot 或行为证据。
4. 验证剩余引用可在当前仓库解析，并运行受影响门禁。排除 vendor、node_modules、录制产物和快照原声。
