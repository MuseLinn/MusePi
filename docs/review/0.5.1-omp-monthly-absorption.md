## 0. 结构事实（决定所有成本）

1. **omp 新增原生 Tern 渲染协议**（`NativeNode` / `describe()` / `handleNativeEvent`）。musepi **0 命中** ✅。凡走 Tern 的 UI 代码不可直接移植。
2. **`packages/tui` 不能对比**：omp 的 tui 是新一代内核；musepi 的 `packages/tui/src` 是分歧的 pi 血统 TUI（24 根文件），真正 UI 在 `coding-agent/src/modes/`（295 文件）。omp 的 `tui/{overlays,native,tools,chat,chrome,status-line,apps}` 大多建在 musepi 缺失的内核上。
3. **`packages/ai/src` 是空白区** ✅：musepi 只有 `auth`、`auth-broker`、`auth-gateway`、`dialect`、`error`、`providers`、`registry`、`usage`、`utils`。无 `images`/`video`/`embeddings`/`rerank`/`transcription`/`speech`/`judgment`。
4. **底子齐备**：`ai/src/error/` 的 33 个错误类与 omp 一致；`auth-retry.ts` 的 `withAuth`/`ApiKey`、`utils/retry-after.ts` 的 `getRetryAfterMsFromHeaders` 均在。硬缺口仅两处：`modelKind` 与 `TYPESAFE_DEFAULT_BASE_URL`。
5. **catalog 的 KDL 规则树**：omp 全仓 **226 个 `.kdl`**，musepi **0 个**。属子系统迁移。
6. **主题系统已在位**：musepi `coding-agent/src/modes/theme/` 103 个主题文件，omp 104 个。唯一实际差值是 `terminal` 段（见 T1-9）。
