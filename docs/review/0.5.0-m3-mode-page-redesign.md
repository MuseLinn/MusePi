# M3 修订稿：design 模式页（创作表单 → 模式化工作台）

> **状态：已批复**（2026-09-27，小袁总"全按推荐"，决策点 5 项全部按稿执行）。本稿修订 `0.5.0-m3.1-creation-surface-design.md`（已批复）的决策点①（入口形态）、④（设计系统轴后置），并吸收实机反馈与 WorkBuddy/OpenDesign 对标。未列出之处沿用 M3.1 稿不变（六面分类法内核、project metadata 双写契约、manifest「无 manifest 不可预览」刻意契约、§5u/token 体系）。

## 1. 修订动机（实机反馈，2026-09-27）

M3.2 交付的创作面板（欢迎页全屏 overlay + 六 tab 表单）实机使用后暴露三个方向性问题：

1. **形态错了**：创作不是"建会话前的配置表单"，而是"一种工作模式"。WorkBuddy 的对标形态是**切换到设计创意模式页**——空态输入框上方一排类型 chip（生成图片/生成视频/品牌设计/视觉海报/运营海报/PPT 设计），输入框下方给可预览的设计风格列表。表单弹窗把"开始创作"变成了"填表"。
2. **字段冗余**：底栏的「项目名」「工作目录」与既有工作目录菜单职能重复——cwd 应复用现有目录切换，项目名默认取目录名。
3. **资产缺位**：OpenDesign 的设计体系选择器（Neutral Modern/Apple/Notion 等品牌体系 + 调色板色卡预览）与模板资产没有对应物；M3.1 决策点④把设计系统轴后置为占位，实机证明它是设计模式的**核心卖点**，不是可选项。

## 2. 目标形态：design 模式页

### 2.1 入口与导航

- 欢迎页 mode chip 选中「设计」→ 进入 design 模式页（占满聊天列的 L2 层，与设置面板同层叠语言，Escape/切回其他 mode chip 返回欢迎页）。**M3.1 的 overlay 骨架与动效全部保留**——改的是内容物：六 tab 表单让位给模式页空态。
- 模式页 = 一个持久工作台：顶行类型 chip、中央输入框、下方设计体系预览 rail。创建会话后进入会话视图，会话头携带完整 `projectMetadata`（契约不变）。

### 2.2 空态信息架构（自上而下）

```
┌─────────────────────────────────────────────┐
│ [原型] [实况产物] [演示稿] [图片] [视频] [音频] │  ← 类型 chip 排（§2.3）
│                                             │
│  ┌───────────────────────────────────────┐  │
│  │ 描述你想设计的界面、风格与情绪…        │  │  ← 输入框（复用 composer）
│  │                          [风格▾] [发送] │  │
│  └───────────────────────────────────────┘  │
│                                             │
│  设计体系                                    │  ← 预览 rail（§3）
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐           │
│  │Neutral│ │Apple│ │Notion│ │ ＋市场│  …     │     色卡+名称卡，横滑
│  └─────┘ └─────┘ └─────┘ └─────┘           │
│                                             │
│  素材：◉ AI 生图  ○ 色块占位      高级 ▸     │  ← 素材策略 + 高级折叠（§4）
└─────────────────────────────────────────────┘
```

### 2.3 类型 chip 排

六 tab 分类法（M3.1 §3）压平为一排 chip，顺序对齐 OpenDesign 类型排：`prototype / live-artifact / deck / image / video / audio`，外加 `template`（会话模板 rail，M3.1 §3.4 机制不变）与 `other`。

- 单选，选中即把 `kind/intent` 写进创作草稿（同 M3.2 的 tab 切换语义）；默认选中 `prototype`。
- chip 只承载**类型**，不再展开表单页——该类型特有的少量字段（平台/保真度/画幅/时长/音色）收进「高级 ▸」折叠区（§4），默认值取 M3.1 逐字段对表的默认列。
- 图片/视频/音频 chip 选中时，「高级」区内联媒体 provider 选择卡（M3.2 媒体子面控件原样搬入），数据源仍是 `media.providers` RPC（video 条目已于 2026-09-27 接线 agnes/agnes-global）。

### 2.4 输入框

复用欢迎页 composer 全部能力（附件/语音/触发词高亮/提及）。placeholder 按选中类型 chip 变化（如视频：「描述镜头、节奏与风格…」）。发送 = `session.create` + `projectMetadata`，与 M3.2 同一管线。

## 3. 设计体系轴（插件化，本稿核心新增）

### 3.1 数据模型

设计体系 = 一套可被会话引用的命名风格资产：

```jsonc
{
  "id": "neutral-modern",           // kebab-case，稳定 id
  "label": "Neutral Modern",
  "description": "…",
  "swatches": ["#0f172a", "#…"],    // 调色板色卡（预览 rail 渲染用，≤6 色）
  "tokens": { /* gui token 覆盖片段 */ },
  "promptSection": { "name": "design-system", "order": 40, "text": "…" },
  "templates": [ /* 可选：该体系自带的会话模板 */ ]
}
```

### 3.2 插件化注册（对齐 registerMediaProvider 先例）

- 新扩展 API：`pi.registerDesignSystem(system)` / `pi.unregisterDesignSystem(id)`，类型入 `extensions/types.ts`（`DesignSystemConfig`），内置 id 保留、扩展 id 撞内置即拒（与 media provider 同一防撞契约）。
- daemon 侧注册表 `src/presets/design-systems.ts`（或并入 modes 聚合层）：`getExtensionDesignSystems()` + 内置预设表（首版内置 4–6 套：Neutral Modern / Apple / Notion / 新粗野 / 玻璃拟态 / 编辑杂志风，token 片段取自 `gui-design.md` 既有阶梯，零新 token）。
- 新 RPC：`design.systems.list`（builtin + extension 合并返回，session-less）。
- 生效链路：选中体系的 id 写入 `projectMetadata.designSystemId`（M3.1 已留占位字段，本稿启用）；会话引导时 prompt composer 把该体系的 `promptSection` 注入（复用 `prompts/composer.ts` 的区块注入通道，与 mode 预设区块同机制），token 覆盖随会话产物 manifest 记录引用（3.5 既有口径）。
- 扩展市场分发：设计体系包作为扩展包的一类内容物（对齐 modes 主题包进 `BUILTIN_EXTENSIONS` 的先例），能力中心可发现/安装。「＋市场」卡跳扩展中心。

### 3.3 预览 rail 组件规格

- 卡片 = 色卡条（swatches 前 4 色等宽拼接）+ 体系名 + 来源徽章（内置/扩展），120×72，横滑溢出；选中态 accent 描边 + 勾选角标。
- hover 浮卡给 description 全文（§5u 浮层规范）。
- 无选中 = 不注入（设计体系是可选项，与 M3.1 `designSystemId: null` 兼容）。
- 动效：卡片入场 stagger 60ms、选中弹簧（`--spring-liquid`），`gui-motion-off` 全归零。

## 4. 素材策略与高级折叠

- **素材策略**：`◉ AI 生图 / ○ 色块占位` 单选（对齐 WorkBuddy「素材不足时的处理策略」），写 `projectMetadata.assetPolicy: "ai-image" | "placeholder"`，默认 `ai-image`；prompt 注入对应指令段（AI 生图 = 产物引用处走 `generate_image`/`agnes_video_gen` 工具链；色块占位 = 产物用色块+标注占位，不触发媒体生成）。
- **高级 ▸**：折叠区承载类型特有字段（平台/保真度/画幅/时长/音色）与媒体 provider 选择；展开状态入草稿缓存（M3.2 的 `sessionDraft` 机制沿用）。
- **消解的字段**：「项目名」删除（会话标题照常由首轮消息生成）；「工作目录」删除（复用欢迎页既有目录菜单，创作会话的 cwd = 当前选中工作目录）。M3.2 的表单底栏整体退役。

## 5. 与既有机制的关系

| 既有 | 处置 |
|---|---|
| M3.2 CreationPanel 六 tab 表单 | 重构为模式页：tab 行 → 类型 chip 排；字段 → 高级折叠；metadata 编译管线（`creation.ts` 校验/双写）**原样保留** |
| 会话模板（`creation.templates.*` RPC、保存为模板 toast、Blank 首位） | 不动；模板 rail 作为 `template` chip 的内容区 |
| mode 预设五区块（design preset 的 prompt/settings） | 不动；设计体系 promptSection 经同一 composer 通道叠加（order 40 在预设区块之后） |
| `media.providers` RPC | 不动（video 条目已补） |
| manifest v1 刻意契约 | 不动；`designSystemId` 引用记录随 M3.4 manifest v2 一并落 |

## 7. 决策点（待小袁总批复）

1. **形态**：模式页（本稿）vs 保留 overlay 表单只加 chip/预览。本稿建议模式页——实机反馈已证明表单形态不成立。
2. **设计体系插件化 API**：`pi.registerDesignSystem`（本稿，对齐 media provider 先例）vs 纯文件目录约定（`~/.musepi/design-systems/*.json`，无代码注册）。本稿建议 API——与扩展 HMR/市场通路同源。
3. **内置体系清单**：首版 4–6 套是否合适；是否有指定必含的品牌体系。
4. **素材策略默认值**：默认 `ai-image`（本稿）vs 默认 `placeholder`（更省 token/更快出稿）。
5. **M3.2 已交付表单的去留**：本稿为整体替换；若希望保留表单作为「高级模式」入口，请在批复中说明（会增加一条长期维护的并行路径，不推荐）。
