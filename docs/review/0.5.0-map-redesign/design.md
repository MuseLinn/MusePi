# 会话地图视图重设计稿（0.5.0 · M1.14）

> 状态：待小袁总审核。审核通过后按本稿实现 SessionTreeCanvas 改造。
> 配套可视化 mockup：[mockup.html](mockup.html)（浏览器直接打开）。

## 1. 问题定义

现状地图视图 = **每条消息一张卡片**（`SessionTreeCanvas`，9985 条消息 = 9985 张 208×76 卡片）：

1. **糊成一片**：线性会话退化成一列密排小卡片，缩略后无法辨认会话脉络；
2. **进视图卡顿**：整树 mount + 全量边路径计算，超长会话要卡数秒（本次已用 content-visibility 缓解排版，但卡片数量级不变）；
3. **信息密度错配**：卡片上的"角色 · 工具名 + 两行摘要"是消息级信息，用户进地图要的是**轮次级脉络**（哪一轮干了什么、哪里分了叉、哪里花了很长时间）。

用户原话：*"地图视图的显示效果很差，不能很清晰展示会话脉络"*。

## 2. 设计目标

把地图的投影单位从 **消息** 改为 **轮**（与折叠/导航/轨迹同一 `isTurnStart` 口径）：

- 164 轮 → 164 个节点，而不是 9985 个；
- 一眼看清：会话主线、分支位置、每轮工作量、顾问介入点、耗时异常轮；
- 节点是**可展开**的：点一下展开轮内消息泳道（时间线），双击跳回对话。

## 3. 布局（对照 mockup）

```
┌─────────────────────────────────────────────┐
│ ← 返回  会话地图 · 164 轮    [适合全部] [−][+] │  ← 顶栏(玻璃)
├──────────┬──────────────────────────────────┤
│ 迷你     │        主线(垂直时间轴)            │
│ 导航条   │  ┌────────────────────────┐       │
│ (密度    │  │ Turn 7 · 排查CI基线错误 │       │
│  剪影)   │  │ 3回复 · 12工具 · 4m32s │       │
│          │  │ ▂▅▇▂▅▂▇(事件构成条)    │       │
│          │  └────────────────────────┘       │
│          │    ║                              │
│          │  ┌─╨──────────────┐               │  ← 分支列(重答/分叉)
│          │  │ Turn 7′ 重答分支 │               │
│          │  └────────────────┘               │
└──────────┴──────────────────────────────────┘
```

### 3.1 轮节点卡片（NODE 208×88）

| 区域 | 内容 |
|------|------|
| 标题行 | `Turn N` 徽章（顾问轮 = 薄荷青 ` Turn N ✦顾问`）+ 轮起始消息摘要（90 字截断） |
| 统计行 | `a 回复 · b 工具 · 用时`（用时取 `roundDurations`，无则首末事件差） |
| 构成条 | 轮内事件迷你泳道（user/assistant/tool/advisor 四色段，宽度∝事件数）——**脉络感的主要来源** |
| 状态点 | 叶子轮 = 金色发光描边；当前所在轮 = 高亮描边 + 呼吸动画 |

液态玻璃：卡片 `backdrop-filter blur + 1px border + 圆角 12`，支线卡片降低不透明度（现状 `stc-node--off` 语义保留）。

### 3.2 分支

- 分支轮**不挤占主线列**：从分叉点横向开一列（现状 lane 布局思想保留，但单位是轮）；
- 分支列头部显示来源摘要（`自 Turn 7 · 重答`）；
- 分支卡左侧 2px 竖线用渐变色（金→紫）标识支脉归属。

### 3.3 轮内展开（第二层）

单击节点 → 卡片向下展开**轮内泳道**（该轮的 user/assistant/tool/advisor 事件行，复用 `EventRow` 组件与轨迹检视器同一套 i18n/颜色），再点收起。展开高度参与布局（同列下方节点推开）——看轮内细节不用切回对话。

### 3.4 导航

- **迷你导航条**（左侧 48px 剪影条）：164 轮的竖向剪影，每轮 2px 高色带（色 = 轮主 kind），视口位置实时映射；点击/拖动跳转（TurnRail 同款 scroll-spy 反过来用）；
- **适合全部**按钮：缩放到全部节点可见（fit-all）；
- 保留 pan/zoom 手势；连线 = 主线垂直渐变线（金色流动渐变，液态玻璃质感），分支贝塞尔曲线。

### 3.5 空态/异常

- 无分支的短会话（<8 轮）：直接纵向居中列表式排布（不强制地图感）；
- 搜索：保留现有搜索框，命中轮高亮、轮内命中消息数徽标。

## 4. 数据结构（实现要点）

复用 `buildTrajectoryTree`（已有，trajectory-data.ts）：

```
turns: TrajectoryTurnGroup[164]   // turn, events[], startMs, endMs, roundDurationMs
```

- 节点位置：主线按序 y 排列（列内间距 16），x = 0；分支列 x = 列号 × (NODE_W + 56)；
- 边：turn N → N+1 主线直连；分支轮边从源轮的右侧中点贝塞尔连入；
- 展开态：Set\<turn\>，展开高度 = events.length × 24 + 16，参与同列后续节点 y 计算；
- advisor 轮：`events[0].kind === "advisor"`，徽章走 `t("advisor")`。

**消息级画布降级保留**：Shift+切地图 或设置开关可回到现有消息级画布（用于调试分支结构），默认轮级。

## 5. 交互一览

| 操作 | 行为 |
|------|------|
| 单击节点 | 展开/收起轮内泳道 |
| 双击节点 | 跳回对话并定位该轮（现有 `requestJump`） |
| 悬停节点 | 浮卡显示轮首消息全文 + 首末时刻 |
| 拖动空白 | pan；滚轮 zoom（以光标为锚） |
| 点导航条 | 视口跳到对应轮（平滑） |
| 右键节点 | 现有菜单（重答/分叉/跳转）原样保留 |

## 6. 验收标准

1. 9985 条会话进地图 < 500ms 可交互（轮级节点 ≤ 实际轮数）；
2. 不缩放状态下一屏能看清 ≥ 10 轮的标题与构成条；
3. 分支位置一眼可辨（支脉列 + 渐变色线）；
4. 单击展开轮内明细、双击跳对话，与导航条/轨迹统计口径一致（164）；
5. 液态玻璃视觉：玻璃卡片、金色流动主线、薄荷青顾问标记。

## 7. 轨迹视图长会话优化(2026-09-23 实施)

针对 164 轮 / 3232 事件的长会话,轨迹面板(时间线 + 分支树)四项性能与交互改动:

1. **时间线默认折叠**:事件数 > 400 的会话进入轨迹面板时全部轮次默认折叠
   (render 期 derived-state 播种,按 entries 身份只算一次,手动展开状态不被重置);
   mode 行新增「折叠全部 / 展开全部」按钮(`.traj-fold-all`,仅时间线且轮数 > 5 显示)。
2. **分支树渐进挂载**:首帧只挂载 300 行,`.traj-tree-sentinel` 哨兵
   (IntersectionObserver, root=listRef, rootMargin 600px) 进视口追加 500 行,
   滚动实测 300 → 800 → … → 3300 平滑增长,切换树模式首帧从数秒降到即时。
3. **模式切换进度反馈**:时间线 ↔ 分支树切换走 `useTransition`,
   pending 期间显示 `.traj-switch-bar` 不确定进度细条;区间跳转到树模式未挂载行时
   自动 `setTreeVisible(全量)` + rAF 重试(≤30 次)直到目标行提交。
4. **跳转调度 rAF+setTimeout 双保险**(`afterPaint`):窗口被遮挡/最小化时
   document.hidden 导致 rAF 暂停,纯 rAF 调度会让区间跳转永远不执行;
   setTimeout(160ms) 兜底保证后台也完成(实机验证:隐藏窗下 scroll 6011 → 77275 落定)。

另:全文件 14 处裸值 `border-radius`(7px/8px/10px/12px/1px 等)按
gui-design.md 阶梯收口为 `--radius-xs/sm/md/lg/xl` 变量,radius token 检查归零。
