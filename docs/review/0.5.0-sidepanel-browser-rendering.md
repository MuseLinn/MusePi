# 右侧面板与内置浏览器渲染：三方对照吸收设计稿（评审稿 2026-09-22）

> 状态：评审稿，待小袁总审核后转 `docs/gui-design.md` 正式章节并动工。
> 触发：内置浏览器在右侧面板的显示与交互问题 + "侧面板渲染方式参考 openchamber / zcode / open-design 深入吸收"。
> 所有锚点 2026-09-22 逐条实证（本地 `openchamber/`、`zcode/`、`open-design/` 克隆）。

## 1. 我们的现状（实测）

### 1.1 面板容器：`ContextPanel.tsx`（1382 行）

- **tab-primary 模型**（docs §3.3.2）：SurfaceTabStrip 即标题，空 tab → 「从这里开始」空态导航（Kimi parity）；`+` 新建、最大化/还原、左缘 4px 拖拽把手（maximized 时禁用）。
- **滚动分层契约**：`browser` 与 `trajectory` 两个 surface **渲染在 feather-scroll 容器外**（`:639-661`，注释：原生视图投影需要精确 CSS rect——**此注释已过时**，见 §3.1-A1），其余 surface（notes/files/artifacts/widget/jobs/agents…）走统一 `FadeScroll`。
- **最大化**：maximized 时 aside 脱离 width 约束，`gui-pane-right--maximized` 覆盖到 rail 之外（`:439-474` 有专门的 rect 修正 effect）。
- 浏览器槽位：pane 内一个空 `<div class="gui-browser-slot">`，ResizeObserver 把 rect + fit-scale 上报给常驻宿主 store（`ManagedBrowserPane.tsx:421-478`）。

### 1.2 浏览器载体：`ManagedBrowserHost.tsx`（117 行，常驻单例）

- DOM `<webview>` guest，**宿主 = App 根的唯一父节点**，按 store rect `position:fixed` 覆盖在槽位上；切 tab 只切 opacity；隐藏 = opacity:0 + 保留布局（两条硬约束注释 `:23-28`：reparent 销毁 guest；display:none 让 capturePage 永不返回）。
- 视口预设 = 宿主 transform scale（页面保持布局宽度做响应式测量，`:71-76`）。
- 该架构继承自「原生视图恒在 DOM 之上」时代。DOM webview 已不受此约束（见 §2.1）。

## 2. 三方对照

### 2.1 openchamber：`BrowserPane.tsx`（927 行）+ `lib/browser/viewport.ts`（147 行）

- **webview 就地挂载**：`<webview>` 是 pane 的直接 DOM 子节点（`BrowserPane.tsx:88-115`），**无 teleport 宿主**；后台 tab "renders hidden"（`:104` 注释），view 消失则下次 mount 重来（`:658`）。iframe 降级兜底（`:59`）。
- **视口三态模型**：`fill | preset | custom`（`viewport.ts:13-17`）+ 具名预设表（10 档，含 iPad/laptop/desktop，`:31-44`）+ `rotateViewport` 旋转 + `clampViewportSize` 240–3840 钳制（`:64-68`）。与我们"预设 + 拖拽把手"等价，但 `fill` 是显式状态而非缺省推断。
- **ContextPanel**（1303 行）同样是 tab 容器 + rail 模式；agent 的 browser.open 经 `registerBrowserOpener` 远程建 tab（`ContextPanel.tsx:462-464`）。
- **启示**：DOM webview 时代 teleport 宿主不是必选项；就地挂载省掉 rect 上报/镜像整套机制。但 teleport 换来两个我们需要的特性：① maximized 时页面浮在面板圆角卡之上（z-900 单层可调）；② blank tab 的 React 起始页与 glass chrome 的分层。**结论：保留宿主架构，把"过时动机注释"清掉并写明现动机**（§3.1-A1）。

### 2.2 zcode：`packages/desktop/src/main/browserView/`（13.5k 行，原生 BrowserView 世界）

- **tab residency 策略**（`browserTabResidencyPolicy.ts`）：单窗 32 tab 上限；LRU 淘汰受**保护矩阵**约束——visible / selected / operationActive / captureActive / audible / mediaActive / loading / downloadActive 全保护，只有"安静的后台 tab"可被 suspend（`:38-53`）。三级状态机 live-visible → live-background → suspend-pending → suspended → restoring（`:3-8`）。
- **截图表面协调**（`browserScreenshotSurfaceCoordinator.ts` 424 行 + `browserTransparentWindowBootstrap.ts`）：mac 隐藏窗口后 attach 的 guest 从未获得合成首帧，需要透明度 0 + showInactive 的一次"隐形 presentation"（`TRANSPARENT_WINDOW_PRESENTATION_GRACE_MS = 100`，`:24`），并发时曾 SIGSEGV。
- **renderer 侧** `PreviewPane.tsx`（1806 行）：文件读取 / 图片与 Office 预览 / markdown+code 渲染 / 路径面包屑的单体预览 pane。
- **启示**：① 我们的 DOM webview 天然免掉截图表面/透明窗引导整套（capturePage 走合成器，无原生 surface 问题）——**不吸收，记录"为何不需要"**；② **residency 保护矩阵值得吸收为策略层**（我们现在所有 tab 永驻，长会话+多 tab 内存只吃不管）；③ PreviewPane 的 office/图片预览丰富度是文件预览面板（FilePane）的远期标杆。

### 2.3 open-design：`FileViewer.tsx`（20k 行单体）+ `CommentSidePanel`（`:4454`）+ `DesignBrowserPanel`

- 纯 DOM 面板范式（web composer，无原生视图问题）：`CommentSidePanel` 评论侧滑层、DesignBrowserPanel 设计资源浏览、PreviewModal（1095 行）全屏预览模态。
- **启示**：侧滑层（slide-over panel）模式可用于我们的 agents 详情/trajectory 详情（已有 docked 雏形，`ContextPanel.tsx:697-713`）；PreviewModal 的全屏预览可作 artifacts 图片/Office 预览的放大路径。均为**远期丰富度项**，不进 0.5.0 关键路径。

## 3. 吸收计划

### A1（本轮落地，修正性）

- **清除过时注释**：`ContextPanel.tsx:639-643` "native WebContentsView projects the slot's exact CSS rect" → 改为现行架构描述（DOM webview 常驻宿主 + 槽位 rect 镜像 + 为何 browser/trajectory 仍在滚动容器外：webview 需要固定布局链 + trajectory 自带滚动列表防高度逃逸）。**动机注释必须与代码同步**，这是本轮顶栏教训的同款纪律。
- **ManagedBrowserHost 头注释补充现动机**：保留宿主的两个现行理由（maximized 分层、blank 起始页 glass 分层），标注"原生视图动机已失效"。

### A2（本轮落地，小交互）

- **blank tab 起始页与 glass chrome 的视觉对齐走查**：实机核对起始页在槽位内的圆角/边距与 §5s 液态玻璃四层配方一致（此前用户反馈右侧面板显示有问题）。
- **视口预设补齐 openchamber 预设表缺口**（iPad mini 768×1024、iPad Pro 1024×1366、laptop 1280×800、desktop 1440×900 中缺的档位）+ `fill` 显式状态对齐三态模型（小改，不动架构）。

### B（评审通过后，策略层）

- **浏览器 tab residency（zcode 保护矩阵简化版）**：上限 16 tab（我们是面板内嵌浏览器，不需要 32）；超过时按 LRU suspend 安静后台 tab（webContents 级 `webContents.fromId(...)` 不可用——webview guest 用 `guest.session`…**技术路径待验证**：DOM webview 的 suspend 等价物是移除 src + 缓存 lastUrl，恢复时 reload——accept reload 代价，或仅做"关闭最久未动 tab"的提示卡片）。**先出技术验证再动工。**

### C（远期，不承诺 0.5.0）

- 文件预览 pane 丰富度（zcode PreviewPane 对标：office/图片/markdown 统一预览壳 + 面包屑）。
- open-design 式 PreviewModal 全屏预览（artifacts/图片）。
- slide-over 详情层推广（agents/trajectory 详情）。
