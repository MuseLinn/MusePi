## 2. 名词定义

- **吸收**：把 oh-my-pi 的做法引入 musepi-omp，并在本仓维护。
- **立即可吸收**：改动独立、不依赖其它子系统迁移、无需触发条件即可开工。
- **子系统迁移**：引入一个新的运行时或代码生成子系统，并重写既有逻辑以适配。
- **parity 快照**：对目录中每个 model id 记录一组解析事实（context window、thinking ladder、modalities、api route、class/family/revision），作为回归基线。

## 3. omp 吸收范围：四类

### A 类：立即可吸收 —— **当前为 0 项**

原因：本轮只核查了两件事。

1. `shouldInlineToolDescriptors` 的 `auto` 分支。两侧语义相同：Gemini 血统 → 内联。
2. KDL 规则体系。属子系统迁移，见 B 类。

所以 A 类没有候选。未运行 divergence sweep，因此不排除存在其它 A 类项。

### B 类：需要触发条件或独立立项

| 编号 | 项 | 现状 | 触发条件 |
|---|---|---|---|
| B1 | KDL 规则体系 + `classifyModel` | omp：`compat/rules/**` 227 文件 / 约 456KB → 生成 `rules.json` 415KB；`compat/taxonomy.ts` 22.5KB。musepi：`classifyModel` 0 命中；`compat/` 为 5 个纯 TS 模块；`identity/` 10 文件 | 满足任一：①新增 2–3 个带 per-model quirk 的 provider；②出现「两处策略互相矛盾」的缺陷 |

B1 的收益：策略变数据；单一出处；加载期检测规则歧义（`AmbiguousOverlapError`）；exact-id 残留强制带注释；与 omp 的差异从代码冲突降为数据 diff。

## 4. 当前 Gemini 内联的实际代价（我方实测）

测量条件：clean cwd，默认工具集（13 个），无 skills，无 context files。

| 模式 | System Prompt part0 | 其中 `## functions` |
|---|---|---|
| `inline=on` | 52,564 字符 / 14,034 tokens | 50,507 字符 / 13,519 tokens |
| `inline=off` | 10,756 字符 / 2,717 tokens | 0 |

System Prompt 差值为 11,317 tokens/请求。

总请求差值小于该值：`inline=on` 会从 provider schema 剥离描述，schema 侧约 2.3k tokens；`inline=off` 相反，描述进入 `tools` 字段，约 10.9k tokens。粗算总数约 16.3k 对 13.6k，即 `inline=on` 仍多约 2.7k tokens。

主要代价在结构：13.5k tokens 占用 System Prompt，压缩小窗口下的历史空间。

缓解手段已存在：设置 → 模型 → Prompt → Inline Tool Descriptors = `off`。
