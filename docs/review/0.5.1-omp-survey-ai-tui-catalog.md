## 2. Deep dives on the strongest candidates

### A. `oh-my-pi/packages/ai/src/judgment/` — best single candidate

1. **What it is.** Typed questions over a JSON state. `Judge.judge()` takes one `JudgmentState` (string / named-field object / array) plus a map of `ChoiceQuestion` ("pick one of L options", `types.ts:23`), `NoulQuestion` (probability a yes/no holds, `:30`), `ScoreQuestion` (position on ordered levels, `:37`) and returns per-question `Answer`s carrying probabilities and a concentration/confidence figure (`:48-72`), plus `Usage`. Three backends: `TypeSafeJudge` (native System One `POST /v1/systemone`, also serving OpenRouter's `/decisions` — `typesafe.ts:36-39`), `TextJudge` (renders the same questions into keyword prompts for any chat model via `chatTextBackend`), and the shared contract. Prompts are static `.md` files — `text-judge.md`, `text-judge-state.md`, `text-judge-retry.md` — matching musepi's own "prompts live in `.md` files" rule. `TypeSafeJudge` rotates credentials on 401/403 via `withAuth` and backs off on 429/5xx with `retry-after` awareness (`typesafe.ts:94-98`, `:149-181`).
2. **omp source.** `oh-my-pi/packages/ai/src/judgment/` — 8 files, **773 lines**: `types.ts` 135, `text.ts` 288, `typesafe.ts` 183, `chat.ts` 89, `index.ts` 4, plus 3 `.md` totalling 38 lines.
3. **Dependencies.** *No third-party and no native deps.* `types.ts:14` imports only `Usage` from `../types` — fully standalone. Backends add only in-repo deps: `typesafe.ts:19` `withAuth` (present), `:20` `AIError` (present), `:21` `getRetryAfterMsFromHeaders` (**present**), `:18` `$env` (present), `:16` `TYPESAFE_DEFAULT_BASE_URL` from catalog `discovery` (**absent** — musepi has no `discovery/typesafe.ts`; only that constant is needed). `text.ts` imports `escapeXmlAttribute`/`prompt` from pi-utils (both present) and `YAML` from `bun`. `chat.ts:1` needs `type` from omptype→`@musepi/musepi-type`, `:3` `retryTransientCompletion` from `oneshot-retry` (**present**), `:4` `completeSimple` from `stream` (**present**).

   Per-file inventory (line counts from `Get-Content .Count`):

   | file | lines | role |
   |---|---|---|
   | `judgment/types.ts` | 135 | `Judge` interface, question/answer types, `JudgmentParseError`, `tokenUsage` — **zero repo deps beyond `Usage`** |
   | `judgment/text.ts` | 288 | `TextJudge` + `chatTextBackend`; renders questions into prompts, format-correction retries, `guardState` option |
   | `judgment/typesafe.ts` | 183 | `TypeSafeJudge`; `JUDGMENT_ROUTES`, credential rotation, retry-after-aware backoff |

4. **Does it assume omp-only infrastructure?** No, and this is the key finding. `TypeSafeJudgeOptions` (`typesafe.ts:59-74`) exposes `apiKey`, `api`, `provider`, `baseUrl`, `model`, `headers`, `fetch`, `timeoutMs` — a caller points it at any System One–compatible endpoint. The catalog `typesafe` KDL rules are a convenience, not a requirement. `judgment/index.ts:1-4` is a clean 4-line barrel. **Not entangled with a provider musepi lacks.**
5. **musepi equivalent.** None. No `judgment/` anywhere under `musepi-omp/packages/ai/src`. Nearest unrelated: `ai/src/oneshot-retry.ts`, `ai/src/utils/empty-completion-retry.ts` (retry plumbing only).
6. **Landing zone.** `packages/ai/src/judgment/` directly. Downstream consumers (git staging, plan gating) are separate larger integrations; the module stands alone.
7. **Absorption cost.** **S** for `types.ts` alone; **S–M (<2h)** for the whole module including the constant and the three `.md` prompts.
8. **Risk.** Low. `isJudgmentApi`-style catalog dispatch stays inert until musepi's catalog gains `typesafe`/`openrouter-decisions`; callers construct the judges directly meanwhile.
