# M5.2 Office 编辑链路 spike（Tiptap / Word 工作副本）

> 2026-11-24。对应 `0.5.0-roadmap.md` M5 5.2/5.3。结论：Word 工作副本采用 Tiptap（MIT），先做「文本 + 粗体/斜体/下划线」，结构化编辑留给后续。

## 起点

`apps/desktop` 已有 Office 工作副本：`office-documents.ts` 把 docx/xlsx/pptx 读成可编辑模型，`FileOfficePreview.tsx` 在编辑态叠加 contenteditable，`FilePane` 负责保存工作副本（编辑不碰原件）。Word 之前只有 `plaintext-only`，没有富文本。

## 选型

| 方案 | 结论 |
| --- | --- |
| Tiptap（`@tiptap/react` + StarterKit，MIT） | 采用。React 绑定、marks、命令链齐全，Open Core 之外不需要 Pro 扩展 |
| Milkdown Crepe（已在用的 Markdown 编辑器） | 不用于 Office。Crepe 的 UI 与 schema 围绕 Markdown，混用会让两套文档模型互相渗透 |
| 直接 ProseMirror | 等价能力但要自己写 React 绑定与命令层，收益只有少一个依赖 |
| docx → HTML → Tiptap → docx（mammoth / html-to-docx） | 不采用。往返会丢样式、编号、表格结构，与「编辑不碰原件、其余字节保留」冲突 |

Tiptap 只装进 `apps/desktop`；`client-core` 与移动端不引入编辑器依赖。

## 已实现的范围

- Word 段落以 Tiptap 文档呈现，段落 ID 保存在节点属性里；文本与 `bold`/`italic`/`underline` 可编辑。
- 不可安全重写的段落（表格、图片、超链接、域、复杂 run）在编辑器中显示为只读「保留块」，保存时字节不变。
- 保存把 marks 投影回 OOXML：每段可拆成多个 `<w:r>`，沿用原 run 的 `<w:rPr>`，只增删 `<w:b/>`、`<w:i/>`、`<w:u w:val="single"/>`；段落属性与包内其它部件不变。
- 结构调整被拒绝：拆段、合段、删除段落、重排、带块级节点的粘贴都会被编辑器过滤，保存前还会再校验一次段落 ID 序列。
- `Ctrl+S` 保存工作副本；恢复引用锚点仍按段落 ID 定位。
- 只读预览仍是 docx-preview 的分页渲染；进入编辑态才切到 Tiptap。

## 格式范围（当前）

| 输入 | 编辑 |
| --- | --- |
| `.docx` 纯 run 段落 | 文本 + 粗体/斜体/下划线 |
| `.docx` 表格/图片/超链接/域 | 只读保留块 |
| `.pptx` 文本框 | 纯文本（沿用既有 surface） |
| `.xlsx` 文本单元格 | 纯文本（沿用既有 surface） |
