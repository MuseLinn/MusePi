> 状态：试点通过（2026-09-30）。四能力实测全绿，HMR 口径实测有明确结论。

## 1. 试点问题与设计稿遗留问题的回答

### 四能力实测结论（全部通过）

| 能力 | 实测结论 | 证据 |
|---|---|---|
| 加载（Loader） | 真实 user 扩展目录（package.json `omp.extensions` 入口，与 plugins/loader 同一发现约定）→ 动态 import → factory 在 cordis fiber 的 apply 内运行 → 命令可调用 | 测试 1：invoke 返回预期值；检视 ACTIVE + 效果标签 |
| 隔离 | 跨扩展重名命令 = 结构化碰撞拒绝（`DynamicExtensionLoadError code=collision`，教学式文案带归属与恢复指引）；卸载 A 不带走 B 的任何登记；factory 抛错不波及其他扩展与宿主 | 测试 2/3/5 |
| 生命周期 | 每次登记 = fiber 效果账本（`ctx.effect`）一条带标签 effect；`fiber.dispose()` 反向回收（interval 停、命令摘除、事件退订）；失败 fiber 立即 dispose 不留半挂载（dsh startHostHalf parity） | 测试 3/4/5 |
| 检视 | `fiber.state` 状态机 + `getEffects()` 诊断树 + 结构化错误归因 + 探针日志 tail | 测试 1/5/7 |

### HMR 实测（设计稿 §8 遗留问题 1 的回答）

平台：Windows 11 + Bun 1.4.2（本机 PATH 版本）。

| 方案 | 探针实测结果 |
|---|---|
| 裸 `import("file:///…?t=N")` 查询串 | ❌ 不击穿：不同 query 返回同一实例 |
| `Bun.plugin` onLoad（file 命名空间） | ❌ 不击穿：缓存按解析路径键，onLoad 只触发一次 |
| 自定义虚拟命名空间（onResolve 拦截） | ❌ 不可用：Bun 1.3.14+ 起 onResolve 对运行时加载模块不触发（legacy-pi-compat.ts 头部已记录的已知限制） |
| **整包暂存复制**（reload 时复制扩展目录到新绝对路径） | ✅ 可靠：新路径 = 新缓存键，入口与子模块改写均拾取 |

**采纳口径：整包暂存复制。** 由此带来的语义变化：reload 的代码拾取粒度从「仅入口」变为「整包（含子模块）」——优于现状；watch 触发粒度契约（AGENTS.md：入口 mtime 触发 reload）不变。

**对设计稿 §5.2 的输入**：cordis 的依赖图级 HMR 在本栈不可用（@deepseek-ai/cordis-plugin-loader 不在依赖树，dsh 的 host-runner 也不用它——dsh 动态包是自包含单文件字符串，天然无子模块问题）。**决策建议：保留现有 watcher 实现 + 我方补丁层（忙会话挂起/agent_end 补做），AGENTS.md HMR 条不改为「Loader 提供」。** cordis 在本栈的职责收敛为：生命周期/效果回收/检视/装配。

## 2. 与 dsh cordis-host-runner 的形态差异（如实记录）

| 面 | dsh | MusePi spike |
|---|---|---|
| 插件来源 | 模型生成的 host/client 代码字符串（零信任前提） | 真实 user 扩展目录（用户自己写的全权限代码） |
| 执行载体 | node:vm 沙箱 realm 内运行 | 宿主进程内直接 import（与现有 loader 同信任级） |
| cordis ctx 暴露 | 白名单 façade（guard.ts，SANDBOX CONTEXT FAÇADE） | **不暴露**：pi.* ExtensionAPI 本身就是 façade，隔离由构造保证 |
| 配置注入 | schemastery 声明 → cordis 注入 `apply(ctx, config)` | 清单字段表（pi-wire 钳制）→ `pi.config` 读取（第三刀） |
| 身份/版本 | registry 铸造 pluginId/packageId/runId + 审批流 | spike 级：扩展名 + 状态记录；审批流属回退保护②排期 |
| HMR | 无此问题（单文件包） | 整包暂存复制 |

## 3. 试点后的收编决策输入

1. **bun 内置插件收编可进入排期**（设计稿 §1 第 2 步）：先包 daemon 服务为 cordis 服务的薄适配已有 `DaemonHostContext.mount` 承载；终端 provider 收编按设计稿 §2 走。
2. **三件套契约**（name/inject/Config）：spike 验证了 name（fiber 命名）与 Config（经 pi.config 面）的落点；inject 对 user 插件按设计稿保持关闭（trust: user 不可 inject 宿主私有服务名），builtin 插件的宿主级 inject 留待收编第一批。
3. **回退保护三件套**先行不变：spike 的「碰撞结构化拒绝 + FAILED 不留挂载 + 能力缺席归因（entry-missing 文案）」正好就是③（禁用兜底）渲染面的归因数据源。
4. **不建议引入 cordis-plugin-loader**（§1 已述）。

## 4. 遗留事项

- spike 运行时未接生产加载路径（与 extensions/loader 双轨）；接线决策随收编 ADR。
- 暂存目录清理：测试 afterAll 清理；生产接线时需按 daemon 生命周期挂清理。
- 探针 API（DynamicExtensionProbeApi）是窄面替身；生产接线点 = ConcreteExtensionAPI 同源工厂 + 每登记 verb 的效果账本化（register* → ctx.effect 映射表）。
