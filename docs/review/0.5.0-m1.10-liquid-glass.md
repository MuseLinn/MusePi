# M1.10 全产品液态玻璃统一设计稿（评审稿 2026-09-21）

> 视觉总纲：**整个产品统一液态玻璃视觉与交互效果，动效丰富流畅，一镜到底。**
> 本文档是 token 映射与动效语言规范，评审通过后按 §7 分批收敛。
> 双基准：client-core `tokens.css`（web/安卓/desktop 共享渲染层）+ desktop-app `gui.css`（桌面壳）。两面的玻璃组件已各自达标（M1 折叠段/turn header/ApprovalCard 均 `--glass-*` 实现），**本稿解决的是"两套词汇"问题，不是从零造视觉。**

---

## 1. 现状盘点

| 面 | 词汇 | 文件 | 状态 |
|---|---|---|---|
| client-core（web/安卓/desktop 共享） | `--glass-*`（bg/bg-strong/border/edge-hi/edge-lo/sheen/shadow，暗色+亮色双档）、`--spring`/`--spring-snappy`/`--spring-bouncy`/`--spring-liquid`（overshoot  entrance 曲线） | `src/styles/tokens.css` | M1 新增组件已全部使用 |
| desktop-app（桌面壳） | `--gui-motion-*`（毫秒时长表：menu-in 130ms / chip 180ms / fade 160ms / height 240-480ms / blur 280ms / roll 240ms / slide-y 6-10px / blur-amt 8-24px）、`--gui-glass-alpha` 滑杆 + 派生 overlay、`--spring*` linear() 曲线 | `src/styles/gui.css :root` | 成熟，有 motion-pack 覆盖机制 |
| 平台现实 | `[data-platform="win32"]` 关闭真 backdrop-blur（性能） | gui.css | **玻璃观感在 Windows 靠 sheen+rim 补偿，blur 缺席** |

**诊断**：两套词汇语义重叠但不互通——同一次交互（如卡片进入）在 transcript 里读 `--spring-liquid`，在桌面面板里读 `--gui-motion-fade-in`。收敛目标不是删掉一套，而是**建立单向映射层**：desktop 壳保留 `--gui-motion-*`（它的 motion-pack 皮肤机制是产品特性），但其取值与曲线锚定 client-core 的玻璃语言；client-core 不引入 `--gui-motion-*`。

## 2. 液态玻璃语言（材质规范）

玻璃 = 四层配方，缺一不可（blur 缺席时后三层独立成立）：

1. **底** `--glass-bg` / `--glass-bg-strong`（卡面 7% / 浮层 11%；亮色 55%/72%）
2. **缘** `--glass-border` + 内 rim（edge-hi 上缘高光 30% / edge-lo 下缘收 7%）——"液态"的读感主要来自 rim 的 1px 高光，不是 blur
3. **泽** `--glass-sheen` 线性渐变（对角 45°，仅浮层/活动卡）
4. **影** `--glass-shadow` 双层（近环 + 远落地）

**层级**（新增组件必须按级取值，禁止跳级发明）：

| 级 | 用途 | 底 | 缘 | 泽 | 影 |
|---|---|---|---|---|---|
| L0 pane | 滚动面板底、输入条 | 无（透明） | 无 | 无 | 无 |
| L1 card | 折叠段、消息卡、工具卡 | bg | border | 无 | 无 |
| L2 float | ApprovalCard、TurnRail hover 面板、lightbox | bg-strong | border + rim | sheen | 近环 |
| L3 overlay | 对话框、GlobalPause、导览 | bg-strong | border + rim | sheen | 双层全量 |

**活态**（玻璃随会话状态呼吸，已落地，收编成规范）：streaming/进行中 → rim 高光换 accent 色、玻璃底升 strong；审批等待 → 进度线（guest）/pulse beam（desktop）+ 玻璃底升 strong；冻结态（已完成轮）→ 回落 L1。

## 3. 动效语言

### 3.1 曲线（统一锚点）

| 语义 | 曲线 | 已有 token |
|---|---|---|
| 常规变形/位移 | spring linear() | `--spring` |
| entrance（ overshoot，"弹入"感） | cubic-bezier(0.34, 1.56, 0.64, 1) | `--spring-liquid`（**两面对齐到此**） |
| 退出 | 无 overshoot，ease-in 化 spring | `--spring-snappy` |
| 俏皮（宠物/彩蛋） | bouncy spring | `--spring-bouncy` |

### 3.2 时长阶梯（desktop `--gui-motion-*` 保留，取值成规范）

130ms 菜单浮层进出 → 160ms 淡入淡出 → 180ms chip/小件 → 240ms 高度形变/滚动类 → 280ms 模糊类 → 480ms 大高度形变上限。**高度形变一律 delta/6 capped**（已有规则）。位移幅度 6px（小）/10px（大）；模糊量 8px/24px。

### 3.3 一镜到底（核心交互原则）

定义：**场景切换不许出现"黑场/闪白/整屏淡入淡出"，共享元素必须从原位置连续变形到新位置**（desktop 已有 `morphFrame` welcome→chat 先例，收编为规范）：

1. **共享元素追踪**：跨场景持续的元素（会话标题、输入框、头像、turn rail）持有稳定 identity（data-morph-id），切换时量取两框 rect，单 rAF 链内 `translate+scale` 插值（morphFrame 已实现 DX/DY/SX/SY 线性化）。
2. **非共享元素**：旧场景元素不淡出——**就地收缩/滑出**（高度形变到 0 + 8px 下滑），新元素从锚点生长。整屏 opacity 动画禁用（GlobalPause 等系统级 overlay 除外）。
3. **会话切换**（当前是硬切）：welcome→chat、chat→chat 之间按 1-2 执行；聊天内部发送消息（composer 上顶、新轮生长）视为同场景增量，不触发场景切换。
4. **时长**：场景 morph 总长 300-420ms（`--spring-liquid`）；高度形变走 §3.2 阶梯。
5. **guest web/安卓侧缺口**：ConnectScreen→会话、移动端返回列表，目前硬切——按本规范补 morph（工作量入 §7 批次 B）。

### 3.4 降级

`gui-motion-off` / `prefers-reduced-motion`：morph 退化为即时切换（无中间帧），玻璃材质保留（材质不是动效）；`[data-platform="win32"]`：blur 量归零，sheen+rim 补强 2%（已有机制，成规范）。

## 4. Token 映射表（落地契约）

| 统一语义 | client-core | desktop-app | 备注 |
|---|---|---|---|
| 玻璃底/强底 | `--glass-bg(-strong)` | `--gui-glass-alpha` 派生 overlay | desktop 滑杆不动，派生值对齐 7%/11% 两档 |
| 玻璃缘 | `--glass-border` | 同名变量已存在则对齐，否则 gui.css 引 client-core 值 | |
| entrance 曲线 | `--spring-liquid` | `--spring-liquid`（desktop 已引用同名） | **已天然一致，写进规范防漂移** |
| 淡入淡出 | 无（直接用 160ms ease） | `--gui-motion-fade-in/out` | client-core 新组件如需淡出，用 `--gui-motion-fade-in` 时长语义，不新建变量 |
| 高度形变 | HeightMorph delta/6 capped | `--gui-motion-height(-max)` | 同一规则 |
| 活态 accent | `.tr-seg--live` / accent rim | 同 | |

**纪律**：新组件先查本表与 §2 层级表；两表没有才提案新增，新增必须双面上报（映射表更新进 gui-design.md）。

## 5. 组件规格（收编现有 + 缺口）

已达标（液态玻璃 + 动效，收编即可）：M1 turn header、工作段折叠/展开、ApprovalCard 双等价物、TurnRail（burger/pacman +  proximity wave）。**展开说明**：Transcript 其余行类（文本/代码/工具）属于内容排版，不套玻璃——玻璃只给"容器与浮层"，内容行保持纸面感，这是"数据卡上 glow 优于 spotlight dimming"既有决策的延续。

缺口（批次排期见 §7）：guest 场景切换 morph；「回到底部」按钮（M1.3 已导出语义，按 L2 float 规格做：ghost 圆钮、accent rim、spring-liquid 入场、点击 morph 到尾部）；折叠段展开的高度形变动画（目前是否动画化待核实，批次 A 顺手统一）；设置面板分组玻璃化程度审计（配合 M2-2.10）。

## 6. 验收

1. 映射表与层级表进 `gui-design.md`（评审通过后合入正式章节，本文档归档 review/）。
2. 逐面板收敛时：biome+tsgo 全绿、该面板无"表外"token（CI 可加 radius/token lint，已有 check-radius-tokens 先例）、motion-off 下无中间帧。
3. Windows 实测：glass 观感与 macOS 并排截图对比（blur 缺席下的可读性）。
4. 动效抽查清单：场景切换无黑场、entrance 全走 `--spring-liquid`、时长全部落阶梯。

## 7. 分批收敛计划

- **批次 A（顺手带）**：M2-2.10 设置面板审计时对齐玻璃层级；「回到底部」按钮（L2 规格）。
- **批次 B（guest/安卓壳）**：ConnectScreen→会话 morph、移动端列表↔会话 morph；composer 浮层升级 L2。
- **批次 C（desktop 壳）**：面板浮层（ContextPanel/DetailsPanel）层级审计到 L2/L3；会话切换 morph 从 welcome→chat 推广到 chat→chat。
- **批次 D（收口）**：映射表 CI lint；双平台截图对比报告；gui-design.md 正式章节替换 review 稿。

---

**评审决策点**：① §2 玻璃四层配方与 L0-L3 层级是否认可；② §3.3 一镜到底五条原则（尤其"整屏淡入淡出禁用"的严格度）；③ desktop 保留 `--gui-motion-*` 词汇、单向映射而非合并，是否认可；④ 批次优先级（B/C 顺序可对调）。
