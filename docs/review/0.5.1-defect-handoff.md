## 交接须知（先读）

1. **不要改 wire 协议**：本单所有修法都建议落在客户端/daemon 边界内；`@musepi/pi-wire` 的 `SessionEntry`/`AgentEvent` 改动会牵动 TUI/mobile/SDK 三端。
2. **不要回退已定的设计决策**：液态玻璃「收起不卸载」与 M1.11 entry 级虚拟化是已评审通过的产品决策（见 `docs/review/0.5.0-transcript-virtualization.md`）。本单里凡要求「虚拟化/增量」的项，都是**把已有机制接到没接的路径上**，不是推翻决策。
3. **P0 里 P0-1（全局事件劫持水位）是唯一会静默丢数据的项**，建议第一个处理，且它可独立验证。
4. **⚠️ 条目请先复核再动手**：尤其是 P0-5、P1-13、P1-14、P2-23、P2-29、P2-30 这类涉及跨文件状态与复杂度的结论。
5. 仓库测试纪律：每条修复请配一个能说出**失败模式**的契约测试（`AGENTS.md` 的 Testing Guidance）；本单「验收契约」列给出建议断言点。

- **dsh 的 Session 格式 v0→v4 迁移与 native 校验体系**：我方 wire 是独立血统（`@musepi/pi-wire`），照搬迁移代数与校验器成本远大于收益。**只吸收做法**：分页/补推一律走 seq 水位 + 非重叠区间校验（即 P0-3）。

- **dsh 轨迹的完整 Definition/Group 引擎**：只取 P1-22 里那两条约束。
