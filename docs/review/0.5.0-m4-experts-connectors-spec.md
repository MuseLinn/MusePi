## 2. 信息架构

### 2.1 能力中心（改造，非重建）

三个 tab：**技能 | 插件 | 市场**（现状）→ **专家 | 技能 | 插件·连接器 | 市场**。插件与连接器合并为一个 tab（同属性"外部能力接入"：扩展 = 进程内插件，连接器 = 进程外 MCP），卡内用类型徽章区分。

- 入口不变：既有 `omp-open-capability` host 事件（M3 3.7d 已带 `detail.tab` 深链）。
- 每个 tab 统一卡面组件（§3.1），搜索/筛选沿用既有 chip 排。
- 绑定可视化：专家详情页"配备"区（技能 n + 连接器 m 行列表 + 可用性态），**不做全关系图**（范围裁剪，见决策点⑤）。

### 2.2 专家中心（新面，桌面端为主）

顶部：搜索 + `我的专家 n` + `制作专家`。来源两段：默认模板（受管只读）/ 我的专家（草稿·已发布·已停用）。分类条"存在真实分类才显示"（workdsh UX §1 parity）。

- **详情**（使用页，非编辑页）：头像 + 名称 + 来源·版本·状态 → 简介 → 擅长领域标签 → 「试试这样问我」示例任务（点击 → 预填 composer 草稿，**不自动发送**；原草稿有内容时给替换/取消选择）→ 配备技能 n（名称/简介/可用·缺失态，缺失给修复入口并阻止召唤）→ 专业设定（经验/方法/边界/成果标准，可展开）→ 头部主操作「召唤专家」+ ⋯ 管理菜单（编辑/复制/停用·启用/归档；默认模板主操作菜单为「复制到我的专家」）。
- 召唤 = 以专家身份起新会话（§4.1 流程），不是往当前会话塞 system prompt。
- **制作专家**：进原生会话走引导对话（`/expert-manager` 类斜杠命令 parity），产出结构化草稿卡（「查看草稿」）；编辑走五组表单（基本信息/专业角色与方法/交付要求/能力依赖/示例任务），桌面宽度上限 760px。保存草稿 ≠ 发布；发布前预览 + 确认按钮。
- 字段约束（workdsh UX §5 默认值）：名称 1–80 字；简介 1–300 字；单段专业内容 ≤16,000 字、四段合计 ≤32KiB UTF-8；标签 ≤8；示例 ≤6（每项 ≤2,000 字）。先存草稿弱校验、发布强校验，超限明确字段错误不截断。

### 2.3 连接器（新面 + composer chip）

- 连接器 tab（§2.1）管全局：实例列表（stdio / Streamable HTTP）、健康检查真实状态（不凭配置显示"已连接"）、增删改、凭据引用（UI 只见"已配置"，不见密钥）。
- **按会话选择**：composer 链形图标开选择浮层；选中后名称 chip 显示在输入框旁；新会话默认不选。daemon 侧只对选中会话开放对应 `mcp__<server>__*` 工具 namespace（其余会话不可见、不可调用）。全局启用态与会话选择互相独立。

## 3. 组件规格

### 3.1 统一对象卡（能力中心全 tab 复用）

卡面字段吸收 open-design 清单语义，全部既有信息源组装，**零 wire 新增**（字段都来自现有扫描/市场数据）：

| 区 | 字段 | 来源 |
|---|---|---|
| 头 | 图标/头像 + 名称 + 类型徽章（技能/插件/连接器/专家/市场包） | 现有各扫描器 |
| 体 | 简介一行（≤3 行截断） | 现有 description |
| use-case | 「适合：xxx」一行（manifest/详情声明的用途查询；无声明则省略，不造文案） | 市场 manifest 扩展字段（复用 M3 3.7d 的 category/tags 约定，加 `use-case` 键） |
| 态 | 启用/停用/缺失/更新可用 徽章 + 版本（技能） | 现有状态机 |
| 预览 | 技能/模板类已有预览卡（SKILL.md 抽屉）；图片预览沿用既有 | 现状复用 |

卡尺寸沿用市场卡栅格（280px+、16px 间距、24px 内边距、四列→一列自适应——workdsh UX §1 parity）。

### 3.2 详情浮层（专家/连接器共用外壳）

复用技能抽屉外壳（portal + fixed、`min(72vh,720px)` 高封顶、§5u 动效契约）。详情 = 使用页；编辑态另开（DialogFrame compact 规格表单）。详情 max-width 800px、≤600px 全屏面板（移动自适应规则 SIZE 类）。

### 3.3 chip 与选择器

- 连接器 chip：composer 输入框旁（现有模型/status chip 排内），accent rim、点击重开选择浮层、× 移除（仅本会话）。
- 技能选择器（专家编辑态「添加技能」）：可搜索真实已安装目录（加载失败/空目录/无结果三态），行 = 名称 + 简介 + 可用态；已选项可识别、不重复添加；同名技能明确选择不按首个匹配；移除只解除引用不卸载。
- 专家选择（召唤入口旁「换专家」）：同一选择器模式。

## 4. 交互契约

### 4.1 召唤流程（专家 → 会话）

1. 详情页点「召唤」→ daemon `experts.prepare`：固定专家修订 + 依赖健康 + 模型可用性校验；必需项不满足阻止并给具体原因。
2. 确认后 `experts.createExecution`：创建绑定记录（专家修订引用、依赖锁摘要、来源）→ 走既有 `session.create` + preset 组合（决策点①机制）→ 新会话以专家 preset 启动。
3. 示例任务点击 = 向**该新会话** composer 预填草稿（一次性 handoff：目标会话 + 期望草稿版本校验，不覆盖用户已写内容、不自动发送）。
4. 专家修订发布新版后：旧会话绑定不自动迁移（不可变引用），详情页提示「有新版本」；用户可手动「升级到此会话」= 新绑定 + 新会话。

### 4.2 连接器隔离契约

- 工具白名单按会话生效：未选连接器 → 会话内零 MCP 工具；选中 A → 仅 `mcp__A__*`；namespace 以 daemon 权威为准，客户端不自行过滤当安全边界。
- 凭据：连接器配置仅存凭据引用；stdio 仅传显式最小 env；HTTP Authorization 服务端解析。密钥不出 credential store、不进 wire、不进日志。
- 断连/失败：composer chip 给真实健康态（经 daemon 心跳），不凭配置显示绿色。

### 4.3 状态与反馈表

首次加载骨架不闪空目录 / 空目录给制作+浏览双引导 / 搜索无结果保留查询可清除 / Host 不可用给原因+重试 / 发布中禁重复提交 / 超时按操作编号查询（不立即失败重试）/ 停用·归档阻止新召唤但可查历史 / 依赖缺失显示具体项并阻断召唤。全部复用 §5u 弹窗与现有错误卡组件。

## 5. 视觉 token 映射
