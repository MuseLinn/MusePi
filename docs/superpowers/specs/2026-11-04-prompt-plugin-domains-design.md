# 提示词域插件化第二阶段设计

## 目标

把内置预设 persona 迁移为真实 Cordis 插件包，再迁移设计/资产简报；易变 context 只在能保持会话与缓存语义时迁移。

## 约束

- 保留 `BUILTIN_TEMPLATE_REVISION` 历史快照和用户自定义预设升级行为。
- 插件停用后其提示词必须消失，预设切换不得叠加或保留旧区块。
- 核心 block 0、工具权限和 OpenCode affinity 不变。
- 不以新注册表包装旧静态副本冒充插件化；activation、文本 owner 和 disposal 必须一致。
- 每域先写失败测试，再实现并验证真实会话重建。

## 方案

1. 为 chat/design/creator 建立独立预设 persona 包，文本迁入包内 Markdown；预设定义只保留工具、模型和组合声明。
2. 设计/资产简报优先复用现有项目元数据和 `registerPrompt` 函数文本，宿主只提供选择状态，插件拥有渲染和卸载。
3. 易变 context 先做去重与角色归属，只有不引入重复消息、缓存前缀回归或权限变化时才迁移到 context provider。
4. 后续再把核心模板按工具 owner 拆分，不在本阶段机械拆完。

## 取舍

一次性把全部模板迁入插件会同时改变升级链、选择状态和缓存，难以验证。先完成真实 persona 包，再处理有宿主状态依赖的域，可以持续交付且保留回滚边界。
