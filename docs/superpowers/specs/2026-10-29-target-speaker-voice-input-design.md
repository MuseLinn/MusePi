# 目标说话人语音输入原型设计

本文定义原型需要验证的产品契约、实时链路、性能预算和声纹录入流程。模型型号、阈值和最终支持档位必须由真实音频与目标机器评测确定；本文中的性能数字是验收目标，不是现有能力或模型实测结果。

## 1. 意图

语音输入只应把机主的话转成可提交内容，并在背景噪声、旁人讲话和双人重叠时尽可能保持转写正确。系统必须区分三个任务：

- 声纹验证判断语音是否属于机主。
- 目标说话人提取从混合音频中取得机主声音。
- 回声消除与语音增强降低播放回声和环境噪声。

任何一项都不能代替另外两项。原型优先防止非机主内容被自动提交，再追求增强后的字准率和延迟。

## 2. 目标、非目标与反目标

### 2.1 目标

- 旁人单独讲话、电视人声和播放回声不得进入正式转写或触发自动提交。
- 机主与旁人同时讲话时，使用已录入声纹提取机主声音，再做声纹复核和 ASR。
- 背景噪声下，增强后的音频在中文 CER、英文 WER 和代码术语识别上优于未增强基线。
- 桌面端和 TUI 共用 daemon 的声纹、提取、增强和门控逻辑，ASR 模型保持可替换。
- 声纹资料只保存在本机，用户可以查看状态、重新录入和彻底删除。
- 未确认、处理失败或性能不足均有明确状态，不静默退化为未过滤转写。

### 2.2 非目标

- 不把声纹当作登录、支付或高风险操作的认证凭据。
- 不承诺回放、仿声、相似声线和任意极端噪声下零误判。
- 不做多人会议的全角色分离日志；系统只关注当前录入的机主。
- 不在原型中训练或微调基础模型。
- 不要求 GPU 才能使用；低速设备可以明确降级，但不得声称仍支持重叠语音提取。

### 2.3 反目标

以下结果即使演示中的 ASR 文本更干净，也视为失败：

- 未确认文本先进入输入框，随后再靠声纹结果撤回。
- 为降低误拒而自动用当前语音更新声纹，导致旁人声纹被吸收。
- 在实时音频回调中执行模型、磁盘 I/O 或等待锁。
- 为追求语音增强而让干净语音的 ASR 结果明显退化。
- 默认保留原始声纹录音、上传声纹或把声纹写入日志、会话和分析事件。

## 3. 方案选择

### A. 声纹门控与降噪

链路短、资源占用低，能过滤旁人单独讲话，但无法可靠处理双人重叠，不满足目标。

### B. 分离日志后选择机主片段

适合离线多人记录，但只给出时间和角色归属，不一定产生干净的目标波形；重叠语音和交互延迟仍难满足目标。

### C. 目标说话人提取、声纹复核与按需增强

采用此方案。目标提取负责重叠语音，声纹复核负责最终准入，增强负责环境噪声。原型必须同时评测干净、噪声、旁人单独讲话和双人重叠，不能只验证模型可以加载。

## 4. 现有约束与归属

- 桌面端目前录制完整 PCM 后调用 `stt.transcribe`，能量 VAD 位于 `packages/desktop-app/src/lib/voice.ts`。
- TUI 通过 `STTController` 向 STT worker 持续送入 16 kHz 单声道 PCM，`StreamEndpointer` 负责能量分段。
- STT worker 已封装模型下载、运行时安装、取消和推理串行化；sherpa-onnx 运行时类型目前只声明 ASR 与 TTS。
- 公共 ASR 输入契约保持 16 kHz 单声道，但回声消除和增强可以按各自模型要求处理 48 kHz 音频，再重采样到 16 kHz。
- sherpa-onnx 可优先承担声纹嵌入和验证。目标说话人提取需要独立选型，不能假定现有 ASR 运行时已经提供该能力。
- 新增 worker 必须复用 CLI worker host 和现有安装形态，不创建第二套进程启动机制。

## 5. 运行时设计

### 5.1 进程与数据流

新增独立的语音前端 worker，避免目标提取与 ASR 共用现有推理锁后阻塞流式分段。ASR worker 保持现有契约。

```text
麦克风原始 PCM ──→ 有界采集队列 ──→ 回声消除
                                      ↓
                              神经 VAD 与分段
                                      ↓
                    机主条件向量 → 目标说话人提取
                                      ↓
                         按需语音增强与重采样
                                      ↓
                         声纹复核与三态门控
                           ↓           ↓
                        接受          不确定/拒绝
                           ↓           ↓
                     16 kHz → ASR    不进入输入框
                           ↓
                高置信接受才允许自动提交
```

回声消除需要扬声器参考信号。桌面端显式启用系统回声消除；原生采集链路必须取得播放参考或明确报告该能力不可用，不能把普通降噪当成回声消除。

神经 VAD 用于减少非语音推理，但不能代替声纹门控。目标提取与增强的先后顺序由原型评测决定；任何顺序都必须在内存中保留原始片段用于对照，并检查增强伪影是否降低 ASR 字准率。原始片段在会话结束、取消或手动处理后立即释放，不写入磁盘。

### 5.2 门控状态

- **接受**：有效语音长度足够，提取结果的声纹分数超过接受阈值，才允许转写进入输入框。
- **不确定**：短语音、分数处于灰区、提取质量不足或多路结果冲突时，默认不调用 ASR、不进入输入框；界面提供“重说”和“本次仍要转写”。用户显式选择后者后，只对该片段执行 ASR 并生成草稿，禁止自动提交。
- **拒绝**：判定为非机主或没有机主语音时丢弃，不调用 ASR，不产生草稿。

自动提交只使用“接受”状态，并继续遵守现有 `stt.submitTrigger`。手动确认只影响本次片段，不更新声纹，也不把一次手动确认升级为永久降低阈值。

TUI 的临时预览同样受门控约束；未确认时只显示处理状态。桌面端需要把当前整段批量调用扩展为可取消的流式会话，避免另做一套浏览器端模型推理。

### 5.3 背压、取消与降级

- 音频回调只复制样本并写入有界队列，不等待模型。
- 队列最多保留 500 ms 待处理音频；即将溢出时进入降级状态并停止未确认输出，不能无限积压后突然提交旧语音。
- 取消、停止和会话切换必须同时终止采集、前端推理和 ASR 请求，迟到结果不得写入新会话。
- 模型只在录音或录入期间推理；空闲时不占用 CPU。模型可以按现有预热策略常驻内存，但必须受统一内存预算约束。
- CPU 持续积压、内存不足或模型不可用时，关闭重叠提取并明确提示；可以保留“降噪 + 声纹门控”保守模式，但默认禁止自动提交。

## 6. 实时性与性能验收目标

### 6.1 延迟定义

“实时”不是每个 20 ms 音频帧都完成一次声纹判断。短语音声纹不稳定，门控需要累计约 1.0–1.5 秒有效语音，再通过流式窗口持续更新。

分别测量以下时间，不用一个总平均数掩盖尾延迟：

| 指标 | 原型验收目标 |
| --- | --- |
| 音频回调阻塞 | 不执行模型、I/O 或锁等待；采集无连续 underrun |
| 待处理队列 | 稳态低于 500 ms，不能随说话时长持续增长 |
| 首次说话人结果 | 足够有效语音到达后，前端结果 P95 再增加不超过 300 ms |
| 持续前端处理 | 降噪、目标提取和声纹合计 RTF 不超过 0.75 |
| 停顿后的前端收尾 | 端点确定后 P95 不超过 500 ms，不含既有 ASR 解码 |
| 状态反馈 | 开始录音后 100 ms 内出现录音/确认状态 |

RTF 为处理耗时除以输入音频时长，必须分别报告单模型和合计值。首次可确认时间还受有效语音窗口限制，不能通过降低窗口长度换取虚假的低延迟。

### 6.2 资源预算

以下为不含既有 ASR 模型的新增预算：

- 在一台无 GPU 的四核低压 x64 笔记本上，持续处理不积压，前端模型总线程不得与 ASR 无约束争抢全部核心。
- 新增常驻内存目标不超过 1 GB；模型下载总量目标不超过 300 MB。候选模型超出时必须作为选型失败报告，不能静默扩大预算。
- 基准报告记录 CPU、内存、操作系统、线程数、模型精度、采样率和是否启用 GPU，禁止只报告“实时”。
- 桌面端记录长任务和音频 underrun；daemon 记录队列深度、各阶段 RTF、P50/P95 延迟、取消耗时和内存峰值，但不记录音频或声纹内容。

### 6.3 准确性门槛

- 固定对抗集中的非机主音频不得自动提交；同时报告非目标接受率，不能把测试集零事件解释成永久零误判。
- 干净机主语音不得因前端处理出现明显字准率退化；以未处理基线做同机对比，原型目标为相对 CER/WER 退化不超过 2%。
- 噪声和双人重叠集必须分别优于未处理基线，才允许默认开启对应增强或提取能力。
- 机主误拒率、非机主接受率、灰区比例与 CER/WER 同等重要；不能只展示成功分离样例。

## 7. 声纹录入设计

### 7.1 用户流程

语音设置提供“只识别我的声音”开关、录入状态、重新录入、验证和删除入口。TUI 提供同等引导与状态，不仅允许修改配置文件。

1. 用户主动开启功能，看到本地处理、保存内容、删除方式和“非身份认证”说明。
2. 下载并加载声纹/目标提取模型后，选择实际使用的麦克风。
3. 在相对安静的环境中，以正常音量和语速朗读四段不同文本；每段约 4–6 秒，总有效语音至少 16 秒，通常总耗时约 20–30 秒。
4. 每段完成即时质量检查；不合格只重录该段，不要求从头开始。
5. 四段通过后，再录一段未参与录入的短句完成验证。
6. 成功后显示“已启用机主识别”；更换麦克风不要求强制重录，但验证失败时引导重新录入。

录入文本只用于覆盖不同发音，不是声纹密码。界面显示有效语音进度，不用录音墙钟时间冒充有效样本量。

### 7.2 质量检查

- 检测权限、设备切换、静音、音量过低、削波和有效语音长度。
- 检查背景噪声与回声是否足以污染条件向量；不合格时要求换安静环境，而不是把噪声录入为机主特征。
- 对四段音频分别提取向量并做两两一致性检查；离群片段可能包含旁人或误录，必须重录。
- 验证句必须独立于录入句。验证失败不能自动降低接受阈值。
- 录入过程可取消；取消或失败时删除临时音频和未完成档案，不留下半启用状态。

### 7.3 保存格式与模型兼容

默认只保存模型生成的声纹向量，不保存原始录音。目标提取候选模型必须支持预先提取并保存机主条件向量；必须长期保存参考波形才能运行的模型不进入默认方案。

档案按操作系统用户隔离，至少包含：

- 档案格式版本和创建时间；
- 声纹验证模型及目标提取模型的标识、版本和向量维度；
- 各录入片段的归一化向量、机主中心向量及必要的校准统计；
- 全局接受/拒绝阈值版本，不保存可还原语音的文本或音频。

验证向量与提取条件向量分模型保存，不能假设可以互换。模型升级导致向量不兼容时，将档案标为“需要重新录入”；由于原音频已删除，不尝试自动迁移。

文件只允许当前操作系统用户读取，不同步到配置目录、会话目录或云端。禁用功能可以保留档案供再次启用；删除操作必须移除全部向量、校准数据和临时文件。

### 7.4 阈值与更新

- 接受和拒绝阈值来自独立说话人验证集及 MusePi 对抗集，不仅根据机主录入样本调参。
- 使用连续窗口和迟滞避免一句话内状态抖动；过短语音默认进入灰区。
- 不自动在线学习，不把手动确认或高分的当前语音追加到录入档案。
- 用户可以显式重新录入。声音、设备或环境明显变化时通过验证流程提示，而非静默改变机主身份。

## 8. 录入界面与动效

### 8.1 布局

桌面端使用一个固定几何的 `DialogFrame`，四段录入和独立验证在同一位置连续完成，不做多页向导。界面只保留标题、当前朗读文本、声环、四个进度点、必要的隐私信息或当前错误，以及一个主操作。

```text
              录入你的声音
             ●  ○  ○  ○

       请用自然语速朗读这句话

     “今天的天气很适合出门散步。”

              ╭────────╮
              │ 动态声环 │
              ╰────────╯

               仅保存在此设备
```

不显示步骤编号、有效语音秒数、声纹分数、模型检查阶段或向量提取状态。进度点表达完成数量，声环表达当前录音状态，当前文本表达用户动作。“仅保存在此设备”是必要的隐私信息，不属于可删除的装饰性描述。技术错误转换为当前可执行的短句，不展示内部模型名称和错误码。

主操作随状态改变：未开始为“开始”，可继续为“继续”，失败为“重试”，全部通过为“完成”。录音期间不堆叠次级按钮；关闭和取消沿用弹窗的统一键盘与焦点契约。

### 8.2 状态反馈

| 状态 | 布局与动效 | 文案 |
| --- | --- | --- |
| 等待开始 | 声环静止，主操作可用 | 当前朗读文本 |
| 正在录音 | 声环随真实音量轻微起伏，外圈随有效语音推进，静音时暂停 | 当前朗读文本 |
| 一段通过 | 外圈闭合，麦克风图标通过 `morphicons` 变为勾，当前进度点点亮 | 不增加成功说明 |
| 换下一段 | 文本淡入并小幅位移，弹窗和声环位置不变 | 下一段朗读文本 |
| 质量不足 | 保留当前段和已完成进度，声环进入警告状态 | “声音太小”“环境有点吵”或“再靠近一点” |
| 独立验证 | 复用同一声环与布局 | 验证文本 |
| 全部完成 | 四个进度点与声环呈现完成状态，主操作变为“完成” | “声音已录入” |

质量不足只重录当前段，不弹出第二层说明框，不打断其他已完成片段。所有成功反馈应简短，完成一段后自动前进；不得用彩带、粒子或持续循环动画打断朗读。

### 8.3 动效与可访问性

- 使用现有 `DialogFrame` 两阶段进出场；局部显隐使用 `Reveal` 或 `HeightMorph`，图标变化使用 `morphicons`，不引入新的动画库。
- 声环由真实 RMS 和有效语音进度驱动，平滑处理不得制造虚假的完成进度。装饰波形标记为 `aria-hidden`。
- 文本切换约 160 ms，位移和时长读取 motion tokens；录音反馈不得等待完整动画才接受下一段音频。
- `gui-motion-off` 和 `prefers-reduced-motion` 下，声环变为静态进度条，文本与状态直接切换，信息不能只靠运动或颜色表达。
- 为辅助技术提供可读的当前进度和状态；状态播报不得随每个音频帧刷新。
- 音效不是必要反馈，只有用户已启用声音时才可使用短促完成音，并遵守现有声音设置。

## 9. 原型评测

评测集至少包含中文、英文和中英混合代码指令，并覆盖：

- 干净机主语音、不同距离和音量、常见麦克风；
- 旁人单独讲话、相似声线、电视人声和短促插话；
- 机主与旁人同时讲话，包含不同相对音量；
- 键盘、空调、街道和混响；
- TTS 播放期间插话、设备切换、取消和连续多次录音。

每类样本保留原始音频、目标参考文本和说话人标签，评测数据不含生产会话或未经授权的个人录音。报告门控结果、CER/WER、代码术语错误、RTF、P95 延迟、内存和降级行为。

原型先证明模型候选满足准确性和资源门槛，再确定产品默认模型。若重叠提取无法在无 GPU 目标机上达标，交付结论必须明确该阻塞，不得用“普通人声门控”冒充完整目标已实现。

## 10. 留给实施计划的决定

- 目标提取、增强和神经 VAD 的具体模型、许可证、ONNX/原生部署方式与线程配置。
- 桌面流式 RPC 的音频编码和事件契约，沿用现有 worker/wire 机制，不沿用大体积浮点 JSON 作为长期流式格式。
- 三态门控在桌面与 TUI 的具体文案、手动确认交互和命令名称。
- 阈值、窗口长度和性能档位的最终值，必须由原型数据确定。
- 声纹档案的当前用户文件权限封装复用哪个中央存储/安全工具；不得新增另一套秘密存储约定。
