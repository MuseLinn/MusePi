## 1. 现状审计（已核实锚点）

### 1.1 内置浏览器（右面板形态）

- 实现：`ManagedBrowserHost.tsx`（117 行，单一稳定父节点下每 tab 一个 `<webview partition="persist:musepi-managed-browser">`，切 tab 只动 opacity+pointer-events）+ `ManagedBrowserPane.tsx`（1040 行 chrome：地址栏/历史/建议/设备预设/开始页）。
- 架构约束（2026-09-12 `<webview>` 迁移实测，gui-implementation §23，**不可"简化"掉**）：DOM 移动即毁 guest；`capturePage()` 在 display:none/零尺寸下永不 settle（隐藏必须 opacity-only）；禁止给元素设 display（flex 上下文撑高度，否则塌成 150px）；菜单/拖把手必须离开面板层叠上下文（portal + gesture shield）；rect 需 200ms 轮询复测位置性布局偏移。
- 设备预设：main 侧 `Emulation.setDeviceMetricsOverride` + UA 覆写（手机 393px / 桌面 1440px / 自适应），host 按 `fitViewport` scale 变换（§23）。
- **已知显示/交互问题（用户报告 + 审计推断，待实机复验）**：
  1. 右栏打开网页后高度/定位异常史（§23 记录 150px 塌缩、rect 过期两类，均有修复但回归面大）；
  2. chrome 占用与可视面积：1040 行 chrome + host 叠层，窄面板（480px 以下）体验未按规格验证；
  3. 无缩放控制（zoom factor）暴露给用户——agent 链路有 `Emulation` 覆写，用户侧没有等价物；
  4. 无响应式调试视口的拖拽改宽交互（zcode `ResponsiveBrowserResizeHandles` 的对应物缺失）；
  5. 开始页/历史与 omnibox 已有（§22），但与地址栏的键盘导航、无痕/分区提示等 zcode parity 项未对齐。

### 1.2 左右面板接线

- 左：会话侧栏（`SessionSidebar.tsx`，含自定义分组、项目头拖拽重排——M2.8 已补插入线）；侧栏折叠态由顶栏 overlay 钮控制（`GuiHeader` TitlebarLeftControls parity）。
- 右：`RightRail.tsx`（489 行 rail 图标列）→ `ContextPanel.tsx`（1382 行，容器：tab 切换、拖拽调宽、最大化、折叠）→ 内容件：`DetailsPanel`（54 行）、`ManagedBrowserPane`、`FilePane` 等按 tab 挂载。
- 接线事实（gui-implementation §23/§24）：宽度拖拽 `use-pointer-drag` + `body.gui-resizing` + 宽度预算是窗口相对（`panel-width.ts`，MIN_CHAT_WIDTH 420px）；最大化锚点测 `.gui-chat-surface`；折叠必须上报（`managedBrowserVisibility`）不能几何推断；面板菜单走 `useFloatingMenu` portal（z-4100）。
- **问题（待复验）**：rail→panel 的 tab 激活与面板折叠/展开之间的状态一致性；panel 折叠后再开，active tab 记忆；窄窗口下 panel 与 composer 换行冲突（§23 已修 footer wrap）；左侧面板在 welcome 态与 session 态的显隐规则是否一致。

### 1.3 顶栏（GuiHeader.tsx，1364 行）

- 结构：左 overlay 簇（侧栏 toggle + project capsule：dev server 运行/停止 + preview + project 菜单）｜中（会话标题 = switcher 触发 + ⋯ 菜单：rename/copy id/share/export/worktree/archive/delete）｜右簇（pause、global pause、terminal、board、right panel、mini chat、open-in capsule、instance 菜单）。
- 已有 openchamber parity（逐条注释在案）：SessionSwitcherDropdown、ProjectActionsButton（dev server 自动发现/停止/URL 侦测）、OpenInAppButton、DesktopHostSwitcher（hosts 可达性 ping）、picture-in-picture mini chat、export markdown、worktree、archive 共享存储。
- **与 openchamber `Header.tsx` 对标后的缺口（用户指认"很多没实现"）**：
  1. **SessionTabsStrip**：openchamber 顶栏有打开的会话 tab 条；我们只有侧栏 + switcher 下拉——多会话并行时顶栏没有常设导航。
  2. **SessionContextUsage**：openchamber 顶栏内嵌上下文用量 chip（tokens，节流稳定化 `isSameContextUsage`）；我们的 ContextRing/usage 在别处（§12），顶栏无入口。
  3. **Git branch label**：openchamber 标题区显示当前分支（worktree/catalog 三级回退 `gitBranchForDirectory`）；我们的分支信息在 StatusCards（§27，transcript 区域内），顶栏没有。
  4. **UpdateInfo**：openchamber instance 菜单内显示远端 daemon 可更新版本；我们的 OTA 是 electron-updater 桌面自更新（§17），**远端 host 的更新提示没有**。
  5. **层级退避缺失（本稿核心问题）**：右簇 8+ 个同权重图标钮横排，无主次——active 态只有微弱底纹，二级功能（board/mini chat/open-in/instance）与一级（terminal/panel）视觉同权，违反 §5s L0-L3 层级语言。

## 2. 对标吸收要点

### 2.1 zcode 浏览器侧板（`packages/ui/src/browser-use/`）

| zcode 件 | 语义 | 我们的吸收方式 |
|---|---|---|
| `UnifiedBrowserView` / `HumanBrowserView` | 人看 vs agent 操作的双重视图统一 | 保留单 webview；吸收"人类操作/agent 操作中"状态指示（我们的 agent highlight 已有 §23，缺用户可见的占用提示） |
| `ResponsiveBrowserResizeHandles` + `useResponsiveBrowserViewportControl` | 视口边缘拖拽改宽（响应式调试） | **新增**：在设备预设模式下给 host 加可视视口框 + 边缘拖把手（受 §23 把手三规则约束：留在面板内/hit-test/shield） |
| `useDesktopZoomFactor` / `browserViewportZoom.ts` | 用户缩放控制 | **新增**：chrome 加 zoom 控件（per-tab，走 CDP `Page.setZoom` 或 Emulation，不毁布局覆写） |
| `useEmbeddedBrowserWheelChain` | 滚轮事件链（嵌套滚动协调） | 审计我们的 wheel 传递是否被 gesture shield 误伤，补测试 |
| `useBrowserScreenshotSurfaceReady/Request` | 截图表面就绪语义 | 与 §23 `capturePage` settle 约束对齐成统一 ready 状态机（显示层给"页面未就绪"占位而非白屏） |
| `BrowserViewportToolbar` | 工具栏信息架构 | 对照重排我们 1040 行 chrome：地址行一级，预设/缩放/历史二级收进 ⋯ |

### 2.2 open-design daemon browser

`apps/daemon/src/browser/{browser-open,browser-use-diagnostics}.ts`：值在"agent 浏览器使用的诊断通道"（打开请求 + 诊断上报），不是面板 UI。吸收点：**诊断/状态上报契约**——我们 managed-browser 的 activity ledger 已有（§23），补用户可见的轻量诊断入口（bridge 端口、tab 数、最近错误）进 instance 菜单或设置 → 工具。

### 2.3 openchamber 顶栏（既有 parity 的补充）

除 §1.3 缺口表外：openchamber Header 用 Tooltip 全量包裹图标钮（5 组 TooltipTrigger），我们的 title 属性是原生 tooltip——层级重排时顺手统一到 RailTooltip/MenuPopup 体系。`WindowsWindowControls` 的内嵌窗口钮在 overlay 模式下我们靠原生 titleBarOverlay（150px 让位），维持现状。

## 3. 设计稿（评审项）

### 3.1 顶栏层级与退避（§5s 层级语言落地）

右簇分三级，**默认态逐级退避**（不活跃即退到下一级的视觉权重）：

| 级 | 成员 | 常态 | 激活态 |
|---|---|---|---|
| P1 一级 | terminal、right panel | L1 底 + fg 图标 | L2 浮起：accent rim + `--glass-bg-strong` + StateIcon morph |
| P2 二级 | board、mini chat、pause 组 | 退避：透明底、fg-faint 图标、无框 | hover/激活升 L1 |
| P3 三级 | open-in capsule、instance、settings | 退避 + 聚合：capsule 保留（open-in 是复合件），instance/settings 常驻最右 | 菜单打开升 L2（portal 浮层本身 L3） |

- **退避规则**：非激活的 P2/P3 图标透明度 fg-faint、无背景；任何按钮不得与 P1 激活态同屏同权重。激活态语言唯一：accent rim + strong 底（§5s 活态规则的壳层版）。
- **左 overlay 簇**：维持 TitlebarLeftControls parity，但 project capsule 的 preview 钮按 P2 规则退避（仅 devRunning 时出现，已是现状，写成规范）。
- **新增（缺口 1-4，按批次）**：
  - **会话 tab 条**（SessionTabsStrip parity）：侧栏折叠或 ≥3 个打开会话时，标题左侧出现 tab 条（segmented capsule，L1），点击切换、中键关闭；与 switcher 下拉并存（tab 条是常设导航，下拉是历史+新建）。**决策点①**：是否做成可关（设置 → 外观）。
  - **上下文用量 chip**：标题行第二行（projectLabel 旁）加 mono 小字 `ctx 45%`，数据走 `session.thinkingInfo`/usage 链路，节流稳定化（isSameContextUsage parity）。窄标题时省略。
  - **Git branch chip**：projectLabel 行前加分支 icon+名（只读展示；切换分支仍在 StatusCards）。数据源 `git status` 既有链路。
  - **远端更新提示**：instance 菜单的 host 行加"可更新 vX.Y.Z"角标（GitHub release 比对，远端 daemon `system.meta.version` 已有）。
- **布局预算**：右簇现状 8 件 + 新增后不得超过 12 个 28px 单元；超出成员强制归入 ⋯ 聚合菜单（新增一个最右 ⋯ 收 P3）。**决策点②**：⋯ 菜单是否现在就加（推荐加，先把 instance/settings 收进去）。

### 3.2 内置浏览器面板交互（zcode 吸收）

1. **缩放控件**：地址行右侧 `− 100% ＋`（per-tab 持久化），实现走 CDP `Page.setZoom`（独立于设备预设的 Emulation 覆写，两者不互踩）；`useDesktopZoomFactor` parity。
2. **响应式视口把手**：设备预设（手机/桌面）激活时，host 外框画 dashed viewport 框 + 右/下边缘拖把手改预设宽（最小 320），实时 `set-device` 回 main 改 `Emulation`；受 §23 把手三规则约束。
3. **截图就绪占位**：guest 未 dom-ready / capture 不可 settle 期间，slot 显示 L1 占位卡（spinner + "页面加载中"），杜绝白屏/死框观感；`useBrowserScreenshotSurfaceReady` 状态机对齐 §23 既有约束。
4. **chrome 信息架构重排**：地址行一级（返回/前进/刷新/地址/缩放）；设备预设与 ⋯（历史/分区说明/诊断拷贝）二级；删除常驻低频件。窄面板（<480px）自动收为仅地址行。
5. **agent 占用提示**：agent 正在操作该 tab 时（activity ledger 已有），chrome 加 2px accent 顶条 + mono "agent 操作中" 细条（与 §5s 活态一致）；人类输入（guest 收到真实输入事件）时暂停提示——HumanBrowserView parity。

### 3.3 左右面板接线

1. **状态一致性契约**：rail 激活 tab ⇄ panel 折叠态 ⇄ 各内容件挂载，收敛到一个 `panelState`（activeTab/open/width/maximized），持久化 `musepi-gui-right`（既有）+ 新增 `musepi-gui-right-tab`；折叠再开恢复 active tab（现状待复验，不一致则修）。
2. **左侧面板**：welcome 态隐藏侧栏的规则与 session 态统一（现状：overlay 簇 pad 逻辑已有，侧栏显隐规则待核对 `app.tsx` 分支）；侧栏折叠动画走 §5s 场景 morph（就地收缩，非整屏淡出）。
3. **拖把手通用化**：右 panel 宽度拖拽（`use-pointer-drag` + `body.gui-resizing` + shield）抽象成共享 hook，供 3.2 的响应式视口把手复用（同一手势三规则只需实现一次）。
4. **窄窗口保护**：panel 最小宽度与 MIN_CHAT_WIDTH 预算已有（§23）；补 panel 最大化态下 rail 的可见性规则（maximized 时 rail 收进 panel 头部，不再占窗口右缘——现状待复验）。
