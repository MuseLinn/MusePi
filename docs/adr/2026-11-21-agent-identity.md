# ADR: Conversation identity and account controls

- Status: accepted

## English

## 11. One identity per conversation: the agent capsule and the account control (2026-11-21)

- **The avatar is conversation chrome, not a row prefix.** A turn used to paint the agent orb (64px) and the user chip (28px) in per-row gutters, so every reply paid 64px + 12px of left width for an identity it shares with the whole session. `ChatView` now passes empty `userGutter`/`agentGutter`, and the desktop transcript collapses those columns at every width (`.gui-transcript .tr-row:has(> .tr-gutter:empty)`, extending §5's ≥641px rule) so the body owns the full row. The gutter API stays: side-session and subagent transcripts still paint an orb, and a row with real gutter content (a forwarded sender badge) keeps its column.
- **One capsule, centered over the transcript (two-line hierarchy, 2026-11-24).** `.gui-agent-capsule` is a 40px glass pill with a 28px `AgentAvatar` leading a stacked copy column. The first line is the agent name plus its lane tag (`Coder` for the workbench lane); the second is a 5px state dot, the live state (idle / working / waiting for an approval) and how long ago the last activity landed (`just now` / `12m` / `3h`), matching the reference bot capsule's identity-over-state rhythm. The orb hides when Settings → Appearance show-avatars is off; the copy remains. The pill still ends inside the 52px band the transcript reserves, and the tall, pinned identity head belongs to the Agent tab (below). It is centered against the **chat column**, not the window, so the rail, the side panel and the right rail re-center it as the column narrows. Under a 720px window the name, separator and recency fold first, keeping the orb, the lane tag and the state clear of the Chat / Canvas switch and the info toggle. It renders in the chat view only: the canvas is a different reading surface with its own top controls and no reserved band, so a pill there would float over its nodes. **Clicking morphs the orb into the Agent tab's avatar**: the capsule avatar is the old view-transition snapshot and the tab's 64px avatar carries `agent-identity-avatar` in CSS, so `morphSurfaceFrom` grows one rectangle into the other; `morphSurfaceBack` plays it back when the capsule folds the panel. With avatars off, the click is a plain state change.
- **The capsule is a control, not a readout (2026-11-21).** The pill is a real `button` with a trailing arrow that appears on hover, on `:focus-visible` and while its tab is open (`aria-expanded="true"` — one state set, so the affordance never depends on the pointer alone). The arrow points right at rest and the same glyph rotates to point left once expanded, in 160ms; the press scales the pill by 3% and springs back. `prefers-reduced-motion` drops both transitions and the scale. The head row stays `pointer-events: none`, so a message underneath keeps its hover and quote pointer; only the pill and the row's real buttons re-enable the pointer, and the pill carries a visible 2px accent focus ring outside its border. The visible reading — agent name, role tag and live state — is the button's accessible name; the action lives in its `title`, never in an `aria-label` that would replace the state (label in name). Clicking opens the agent info tab in the right panel (expanding a folded panel); clicking again while it is the visible tab folds the panel, the rail's own toggle rule.
- **The agent info tab (`session.agent`).** A tertiary surface — launched by the capsule, never by the rail — addressed by the session id so one session has one tab. Its identity head is the tab's one vertical, pinned element: the orb at its full 64px centered at the top, the agent's name, role tag and live state stacked beneath it, and the session title as the last line. The head is `position: sticky` on a full-bleed glass band, so the model list, the thinking ladder and the metadata scroll underneath it while the identity stays readable — the chat capsule never grows into this shape. The tab's scroller is a `FadeScroll`, but this one drops the top feather and keeps the bottom: a pinned, opaque band sits exactly on the top stop, so the generic mask (transparent 0 → opaque 20px) dimmed the band's edge and the top third of the orb, which is the opposite of the readable identity the head exists for. The exception is scoped by ancestry (`.gui-fade-scroll:has(> .gui-agent-info)`), and the geometry test samples the real container's pixels so it fails if the exception goes away. Below the head, the model area is one **collapsed card** that reads the running model as its friendly name over the `provider/id` reference with the current thinking level as a trailing chip, and opens the searchable model list — the same favorites/recents/provider sections as the composer's old menu, not a second picker — only when the card is activated. Activating the card moves focus to the search field, Escape folds it back and returns focus to the card, and a pick folds it with the selection kept. Beneath it, the model's real thinking ladder is a discrete slider (`off` only when the model has efforts, `auto` always, rungs above the model's ceiling visible but unreachable and drawn as hollow dots) whose head is ONE line — `Thinking level` beside the current level, with `Auto · <level>` replacing the level while Auto is selected — and which carries NO caption row under the track: each rung names itself in its dot's `title` (behind a padded hover band, since an inert 4px dot cannot be hovered) and `aria-valuetext` names the rung a release lands on. The track is the inline effort-bar shape rather than a settings field — a 28px hit pill whose 22px groove is inset 3px a side with an inset hairline, detents on the groove, the fill running from the pill's edge through a light handle — drawn in our accent family, never a neutral handle on a foreign blue. The settings detent ladder renders the same track and differs only in its head; the pointer drives a fractional position (the thumb sits at the pointer from the press frame, never hopping to a detent and back), the nearest reachable detent is the magnetic target that the label and `aria-valuenow`/`aria-valuetext` name, and the release eases the thumb onto it and commits once (cancel restores, keys step one rung through the same snap), and a refused write rolls the whole block back. Both ladders and the two native `.gui-range` opt-ins (notification master volume and companion size) draw from one slider family — `--gui-slider-*` in `gui-chat.css` and the one `SliderTrack` primitive: one inline pill with an inset groove, gradient fill, detent dots, a text-ink handle that lifts on hover and while dragged, one focus halo, one disabled opacity. The handle is text ink, not accent: it sits on the accent fill, and the accent is mid-luminance in both schemes, so an accent disc needed a rim to separate it from its own fill and that rim read as a heavy dark ring at this size. That family covers the ladders and those two opt-ins only; the SketchPad thickness, browser device-toolbar, screenshot stroke-width and `.tr-ui-range` sliders plus the mobile `VoicePanel` rate stay outside it until they adopt it in their own scope (the exact list is in `docs/gui-components.md`). Desktop voice settings have no slider — `tts.rate` renders as the rolling counter. The two ladders are now one track with two heads: the settings ladder keeps `.gui-slider--detent` for its 210px row width and its value above the track, while the agent slider fills the panel. The tab also carries the session metadata that no longer needs composer chips: working directory, context usage and cost, pending approvals as a jump to the chat's approval card, session id and plan/goal mode. Context usage and spend are the host-computed **`contextUsage` session projection** (`packages/coding-agent/src/session/session-projections.ts`): the daemon folds committed assistant settlements in O(1), samples the anchored live stats at turn / compaction / branch-move / model-switch boundaries, and pushes whole values — a baseline on `session.resume` and one `projection` stream frame per committed event whose view changed. The composer ring, the Context tab, this pane and the session info card all read the same client store (`GuiSessionState.projections`); no surface polls `session.contextUsage` any more. The wider `/context` facets — threshold, snapcompact, breakdown — are a one-off user-initiated read when the popover or `/context` card opens, never a background tick. Three entrances — subagents, context, background jobs — plus memory in Settings — replace navigation the composer never should have carried. Model and thinking are the only writes; a refusal is shown in the tab and as a toast, and the thinking write is optimistic with a rollback. A refused model switch also puts the list highlight back on the model the daemon kept. A failed `thinkingInfo`/`contextUsage` read is a distinct unavailable state with a retry (never a permanent "loading"), and a post-write re-read that fails is announced instead of leaving stale numbers.
- **A centred element presses in place, never sideways (2026-11-22).** The pill is absolutely centred with `left: 50%`, so its `transform` carries two unrelated jobs: the centring (`--gui-capsule-shift: translateX(-50%)`) and the press gesture (`--gui-capsule-press: scale(0.97)` under `:active`). They are separate custom properties because a surface may centre the pill by LAYOUT instead — the settings effects preview does, `.gui-effect-preview-identity` is a flex row with `justify-content: center` — and such a surface must zero only the shift. Before the split, `:active` re-declared the whole transform with `translateX(-50%)` in it, so pressing the preview pill shifted it half its width left: the "not a press, a jump" the user reported. The rule is general: **a press is a scale, never a displacement, and any centring transform a control carries must be a variable a host can neutralise without losing the gesture.** `test/agent-capsule-geometry.test.ts` holds the REAL `:active` state on both pills through CDP `CSS.forcePseudoState` — an injected rule that sets `--gui-capsule-press` directly would only prove the variable works, and stayed green with the bug restored — and asserts the painted centre x is unchanged between rest and pressed in the chat AND in the preview, with the pill measurably narrower in both. The preview's zero must be `translateX(0)`, not `none`: `none scale(0.97)` is an invalid transform and would drop the press entirely.
- **The agent tab opens in two phases (2026-11-22).** Opening the capsule mounts `session.agent` in the same click that changes the panel's width, and the tab's model catalogue is a row per model — hundreds in a real catalog. Measured on a 260-model catalog: the tab's first render is ~20ms, but the commit that mounted the folded list cost ~316ms (40 models ~103ms, 2 models ~50ms), which is the stall the user reported as 卡顿. The rule: **a heavy list mounts after the first frame or on demand, never behind a folded disclosure on mount.** The catalogue now mounts on the first disclosure open and stays mounted (its query and scroll survive a fold), and the list itself is **budgeted**: the first open mounts 30 provider rows and a `Show more` row appends 40 at a time, so a 260-model catalog never pays the whole mount. Favorites and recents always render in full (they are pinned, usually few, and the favorites section owns drag ordering). `ModelSelector` seeds a new mount from a module-level catalog cache keyed by the read it makes (`session:<id>` / `registry`) so a re-mount paints rows on its first frame, while the mount still re-reads, so `models.yml` edits and `models.changed` broadcasts keep working. The seed is bounded and never lies: a FAILED re-read deletes the key and clears the rows (a model the daemon no longer serves must not stay listed and selectable with no error state), and the map is least-recently-used with a small cap, because nothing tells the module when a session closes. The thinking ladder is deferred one painted frame (`useAfterFirstPaint`) — it is cheap, but the identity shell should never queue behind anything. After: ~22ms for the same 260-model open, with only the first 30 rows mounted. The guards are `test/agent-info-pane-open-cost.test.tsx` (first frame reads no catalog and builds no rows; the list appears only after the disclosure opens; a re-mount seeds from the cache; a rejecting re-read leaves no rows and poisons no later mount).
- **The right panel folds on the compositor (2026-11-22).** The fold used to animate `width` over 320ms, which re-laid out the panel's whole subtree and reflowed the chat column on every frame — the transcript is a flex sibling, so each intermediate width moved every message row, and opening the capsule spent its first third of a second reflowing text it was not changing. The closed state now snaps its box (`width: 0`) and the motion lives in `transform` + `opacity` on the panel's children (a short slide towards the rail plus a fade), both compositor properties. The box snaps ONCE, at 220ms, and the card-gutter `margin` snaps on that same frame: dropping the gutter on frame 1 while the panel is still full width grew it 8px right into the freed space (the 收起时面板会突然放大一点 report), so `width` and `margin` are one delayed, zero-duration pair. Two children keep their own motion and are excluded from the contents rule: the seam band (fixed, self-centring, hidden while folded) and `.gui-agent-dock`, whose (0,1,0) drawer recipe the panel's (0,2,0) rule would otherwise beat — replacing its `visibility 0s linear 200ms` with a fade, so the drawer hid on the first exit frame and slid out invisibly. The panel still folds, still animates, `aria-expanded` on the capsule stays honest and the tab stays keyboard-reachable; only the per-frame layout cost is gone. `prefers-reduced-motion` and `gui-motion-off` land on the target state with no slide. `test/panel-fold-reflow.test.ts` samples the panel's width, left edge and gutter frame by frame (they hold until the snap) and the dock's `visibility` through its exit (visible while it slides, hidden only after).
- **A session's agent has a role, and the role is data (2026-11-22).** Every session row carries `agentRole: { id, name? }` from the daemon: a main workbench session is `coder`, a task subagent keeps its own definition name (`sessionInfo.agentName`, e.g. `sonic`), an advisor transcript is `advisor`, and a session recorded before roles existed (or a row with no identity facts) falls back to `coder`. `id` is the contract — it drives `data-agent-role` and survives an unknown lane; the readable label is localized by the client (`Coder`/`编码`, `Subagent`/`子代理`, `Advisor`/`顾问`) and a subagent's own definition name is its name. The capsule shows the name plus the role tag, the Agent tab's head shows the name with the role tag under it, and neither relabels a subagent or an advisor as the workbench coder. A future lane (a bot) adds an id on the daemon side; the client renders an id it has no label for instead of dropping the identity.
- **The session composer no longer carries model or thinking chips.** Attachments, mode, approval, microphone, focus and send stay; the welcome composer keeps its chip because a new session has no capsule yet to open the tab from. The right-panel side session keeps it too: `session.agent` addresses the active chat, so a side session has no capsule and asks `SessionComposer` for the chip (`keepModelChip`), which keeps its model selector; thinking stays in the Agent tab, and a side session offers no thinking control.
- **Pinned, not faded.** The capsule is chrome: scrolling moves the rows beneath it and leaves the pill's box and opacity untouched. The live state is worth reading at any scroll position, and a fade would hide the agent exactly while a long answer is being read. Focus mode hides it with the whole head row, where the transcript is hidden too.
- **The user picture is the account entry.** The rail's settings gear, shortcut button and remote-access button collapsed into one control in the bottom-left corner: `UserAccountButton` (`AppRail.tsx`) resolves the same three-source picture the chat bubble used (GitHub photo → pixel face → initial letter, `punk`, `initial`), adds a connection dot, and opens a menu that owns the account and the app: Settings, keyboard shortcuts, workspace remote access and disconnect (disabled while nothing is connected). Three rows that used to sit here have one home each, because two adjacent popovers repeating them with slightly different lists read as two answers to one question: **session sharing** belongs to the session header (which has the session; this entry must work with none open), **host switching** belongs to the instance control in the same rail footer (which already lists every host with live status), and **instance management** belongs to that control's `InstanceManagerDialog` (which covers both axes — where the daemon runs, where the files live) rather than to a second, endpoint-only manager. No settings gear remains in the rail, and the sidebar footer — still rendered by hosts other than the desktop app — mounts the same control, so both seats reach settings through one entry. The ⌘, shortcut and the welcome/no-session shape keep settings and workspace remote access reachable.

## 中文

## 11. 一段会话只有一个身份：智能体胶囊与账户入口（2026-11-21）

- **头像是会话层的外壳，不是每一行的前缀。** 此前每一轮都在行内 gutter 里画助手小球（64px）和用户头像片（28px），于是每条回复都为「整个会话共用的身份」付出 64px + 12px 的左侧宽度。现在 `ChatView` 传入空的 `userGutter`/`agentGutter`，桌面转录在所有宽度下撤掉这两列（`.gui-transcript .tr-row:has(> .tr-gutter:empty)`，把 §5 的 ≥641px 规则扩到全部宽度），正文占满整行。gutter 接口保留：侧边会话与子代理转录仍会画小球，行内确有内容（如转发的发送者角标）的行仍保留该列。
- **一个胶囊，居中悬浮在转录上方（两层信息层级，2026-11-24）。** `.gui-agent-capsule` 是一枚 40px 玻璃药丸：28px 的 `AgentAvatar` 领着一列堆叠文案——第一行是 agent 名称与角色短标签（工作台通道是 `Coder`/`编码`），第二行是 5px 状态点、实时状态（空闲 / 工作中 / 等待批准）与最近一次活动距今多久（`刚刚` / `12 分钟前` / `3 小时前`），与参考 bot 胶囊「身份在上、状态在下」的节奏一致。设置 → 外观关闭「显示头像」时只去掉小球，文案列保留。药丸仍落在转录预留的 52px 头部带内；竖向、放大的身份头属于 Agent 标签页（见下）。它以**会话列**而非窗口为居中基准，因此左栏、侧边面板、右侧面板改变列宽时它跟着重新居中。窗口窄于 720px 时先收起名称、分隔线与时间，让小球、角色标签与状态避开 Chat / Canvas 切换与信息开关。它只在对话视图出现：地图是另一种阅读面，有自己的顶部控件、也没有预留带，药丸放在那里会浮在节点上方。**点击时小球会共享元素转场到 Agent 标签页的头像**：胶囊头像作为旧快照，标签页 64px 头像在 CSS 里承接 `agent-identity-avatar`，由 `morphSurfaceFrom` 把一个矩形生长成另一个；胶囊再点收起面板时由 `morphSurfaceBack` 反向播放。关闭头像时，点击就是普通的状态切换。
- **胶囊是控件，不是读数（2026-11-21）。** 药丸是真正的 `button`，尾部箭头在悬停、`:focus-visible` 与标签页打开（`aria-expanded="true"`）这同一组状态下显形，不依赖指针单一通道。箭头静止朝右，展开后同一字形转成朝左，160ms；按压时整体缩到 97% 再回弹；`prefers-reduced-motion` 下去掉过渡与缩放。头部整行仍是 `pointer-events: none`，下面第一行的悬停与引用按钮照常可用；只有药丸和行内真实按钮恢复指针，药丸获得一圈不贴边的 2px 主题色焦点环。可见读数——agent 名称、角色标签与实时状态——就是按钮的可访问名称；动作只放在 `title`，不用 `aria-label` 覆盖状态（label in name）。点击在右侧面板打开 Agent 信息标签页（面板收起时先展开）；它已是可见标签页时再点则收起面板，与图标栏的开关语义一致。
- **Agent 信息标签页（`session.agent`）。** 第三类表面——由胶囊打开，不占图标栏——以会话 id 为地址，一段会话只有一个。身份头是标签页里唯一的竖向、吸附元素：64px 小球居中在顶部，agent 名称、角色标签与实时状态依次堆在下方，会话标题作为最后一行，`position: sticky` 的整幅玻璃带让下方分区从它下面滚过，身份始终可读——聊天胶囊绝不会长成这个形态。这个标签页的滚动容器是 `FadeScroll`，但它只保留底部羽化、去掉顶部：吸附的不透明玻璃带正好压在顶部渐隐带上，通用配方（顶部 `transparent 0` → 20px 处不透明）会把身份头的上沿和小球顶部压暗，与「身份始终可读」正好相反。例外按祖先限定（`.gui-fade-scroll:has(> .gui-agent-info)`），几何测试直接采样真实容器的像素，规则一旦被删就会失败；**折叠的模型卡片**——平时只显示当前模型（友好名在上、`provider/id` 引用在下）与当前思考强度的尾随标签，点击卡片才展开可搜索的模型列表（沿用输入框旧菜单的收藏 / 最近 / 按提供商分组，不是第二套选择器）。展开后焦点落在搜索框；Esc 收起并把焦点还给卡片；选中后同样收起且保留选中项。卡片下方是模型真实思考阶梯的分档滑块（仅当模型有档位时才出现「关闭」，「Auto」始终在，模型上限以上的档位可见但不可选、画成空心圆点）：标题行**只有一行**——「思考强度」与当前档位并排，选中 Auto 时由 `Auto · <档位>` 取代档位本身；轨道下方**没有标签行**，每一档把名字放在自己圆点的 `title` 上（并配一条加宽的透明悬停带，因为不可交互的 4px 圆点无法被悬停），`aria-valuetext` 报出松手会落到的档位。轨道采用紧凑力道条的内嵌形态而不是表单字段：28px 命中胶囊内是高 22px、上下各内缩 3px 的凹槽，配内阴影发丝线，档位点落在凹槽上，填充从胶囊边缘一直穿过浅色滑块，配色沿用我们自己的强调色族，而不是「中性手柄 + 外来蓝」。设置页的预设阶梯渲染同一条轨道，只有标题行不同；指针给的是**连续位置**（滑块从按下的第一帧起就停在指针处，不会先跳到某一档再回来），最近的**可达**档位是磁性目标、读数与 `aria-valuenow`/`aria-valuetext` 都报这个名字，松手时滑块缓动吸附到该档位并只写入一次（取消回到原档位，方向键走同一条吸附路径逐档移动），写入被拒绝时整块回滚。两套阶梯与两个主动接入的原生 `.gui-range`（通知主音量、桌宠尺寸）共用一套滑块族——`gui-chat.css` 里的 `--gui-slider-*` 与唯一的 `SliderTrack`：同一条轨道、渐变填充、档位圆点、悬停/拖动时放大的文字色滑块、同一个焦点环与禁用透明度。滑块取文字色而不是强调色：它落在强调色填充上，而强调色在两种配色下都处于中间亮度，强调色圆盘需要一圈描边才能和自己的填充分开，那圈描边在这个尺寸下读成了一圈沉重的深色环。该族只覆盖两套阶梯与这两个原生 range；画板笔宽、浏览器设备栏、截图描边、`.tr-ui-range` 四处滑块与移动端 `VoicePanel` 语速仍留在族外，待各自 scope 收敛（完整清单见 `docs/gui-components.md`）。桌面端语音设置没有滑块——`tts.rate` 渲染成滚动数字。两套阶梯现在是「一条轨道、两个标题行」：设置阶梯用 `.gui-slider--detent` 保留该行 210px 的宽度与轨道上方的数值，Agent 滑块铺满面板。标签页还承载不再需要占据输入框的会话元数据：工作目录、上下文用量与花费、待批准项（点击跳到聊天里的批准卡片）、会话 ID 与 plan/goal 模式；上下文用量与花费来自 host 计算并推送的 **`contextUsage` 会话投影**（`packages/coding-agent/src/session/session-projections.ts`）：daemon 以 O(1) 折叠已提交的 assistant 结算，在 turn / compaction / 分支切换 / 模型切换边界采样一次锚定的实时统计，然后推送整值——`session.resume` 带 baseline，之后每个改变了 view 的已提交事件推一帧 `projection`。输入框圆环、Context 标签页、Agent 标签页与会话信息卡读的是同一份客户端 store（`GuiSessionState.projections`），没有任何界面再轮询 `session.contextUsage`。更宽的 `/context` 字段（阈值、snapcompact、breakdown）只在用户打开圆环弹层或 `/context` 卡片时读取一次，不走后台定时器。子代理、上下文、后台任务三个入口加设置里的记忆，取代输入框不该承担的导航。只有模型与思考两处写入；失败会同时显示在标签页和 toast 里，思考写入先乐观更新、失败回滚。切模型被拒绝时，列表里的勾选也回到 daemon 保留的旧模型；`thinkingInfo`/`contextUsage` 读取失败是一个独立的「无法读取」状态并带重试（不会一直停在加载中），写入成功但重读失败也会明说，而不是留下过期数字。
- **居中的元素在原地按压，绝不横向位移（2026-11-22）。** 药丸靠 `left: 50%` 绝对居中，因此它的 `transform` 同时承担两件互不相关的事：居中（`--gui-capsule-shift: translateX(-50%)`）与按压手势（`:active` 下的 `--gui-capsule-press: scale(0.97)`）。两者必须是各自独立的变量，因为有的表面改用**布局**居中——设置里的效果预览就是 `.gui-effect-preview-identity` 一行 flex + `justify-content: center`——这种表面只应把位移清零。拆分之前，`:active` 重新声明了完整 transform（里面带着 `translateX(-50%)`），于是按预览里的药丸会左移半个自身宽度：这正是用户说的「不是按压，是往左跳」。这条规则是通用的：**按压只是缩放，不是位移；控件身上任何用于居中的 transform 都必须是宿主可以清零、又不会丢掉手势的变量。** `test/agent-capsule-geometry.test.ts` 通过 CDP `CSS.forcePseudoState` 让两枚药丸真正进入 `:active`——注入一条直接设置 `--gui-capsule-press` 的规则只能证明变量可用，把 bug 还原后它照样全绿——并断言绘制出的中心 x 在静止与按压之间不变（真实会话与预览两处），且两处都确实变窄了。预览侧清零必须写 `translateX(0)` 而不是 `none`：`none scale(0.97)` 是非法 transform，会把按压整个丢掉。
- **Agent 标签页分两阶段打开（2026-11-22）。** 点击胶囊会在改变面板宽度的同一帧挂载 `session.agent`，而该页的模型目录是每个模型一行——真实目录动辄数百行。在 260 个模型的目录上实测：标签页首帧约 20ms，但挂载那张折叠列表的那次提交要 ~316ms（40 个模型 ~103ms，2 个模型 ~50ms），这就是用户说的卡顿。规则是：**重列表要么在首帧之后挂载，要么按需挂载，绝不能在挂载时就躲在折叠的披露区里建好。** 目录现在改为首次展开时挂载并保持挂载（查询与滚动位置在折叠后仍保留），列表本身也改为**预算式**：首次展开只挂载 30 行 provider 模型，底部「显示更多」每次再追加 40 行，260 个模型的目录不会再为整表挂载买单；收藏与最近始终全量渲染（它们是用户钉住的少量行，收藏区还承载拖拽排序）。`ModelSelector` 会用按读取键（`session:<id>` / `registry`）索引的模块级目录缓存来**播种**新挂载，所以重新挂载的首帧就有行，而挂载本身依旧重新读取，`models.yml` 外部修改与 `models.changed` 广播照常生效。播种是有界且绝不撒谎的：读取**失败**时删除该键并清空行（daemon 已不再提供的模型不能继续列着、可选中、还没有任何错误状态），缓存本身按最近使用上限淘汰——因为没有任何事件会告诉这个模块某段会话已经关闭。思考强度梯延后一个已绘制的帧（`useAfterFirstPaint`）——它本身很轻，但身份外壳不该排在任何东西后面。改后：同样 260 个模型的打开约 22ms，且首帧只挂载前 30 行。守卫是 `test/agent-info-pane-open-cost.test.tsx`（首帧不读目录、不建行；列表只在展开后出现；重新挂载由缓存播种；读取被拒绝后不留行、也不污染后续挂载）。
- **右侧面板在合成层折叠（2026-11-22）。** 折叠原本用 320ms 的 `width` 过渡，逐帧重排面板整棵子树，也逐帧让对话列重排——转录是它的 flex 兄弟，每个中间宽度都会推动每一行消息，于是打开胶囊的头三分之一秒花在重排并未改变的文字上。现在收起态直接落到 `width: 0`，动效改为面板子元素上的 `transform` + `opacity`（朝图标栏的一小段滑出加淡出），两者都是合成属性。盒子的变化只发生**一次**、在 220ms：卡片外距 `margin` 与 `width` 在同一帧一起落——若 margin 在第 1 帧就掉而面板仍是满宽，盒子会先向右长出 8px（即「收起时面板会突然放大一点」的报告），所以两者是一对「延迟 + 零时长」的切换。有两个子元素保留自己的动效、被排除在内容规则之外：一是接缝拖动带（fixed、自带居中、折叠时本就隐藏），二是 `.gui-agent-dock`——它是 (0,1,0) 的抽屉配方，面板这条 (0,2,0) 规则会盖掉它的 `visibility 0s linear 200ms`，换成淡出，于是抽屉在第一帧就隐藏、200ms 的滑出全程不可见。面板照旧折叠、照旧有动效，胶囊的 `aria-expanded` 依旧诚实，标签页依旧键盘可达；去掉的只是逐帧布局成本。`prefers-reduced-motion` 与 `gui-motion-off` 直接落到目标态、不滑。`test/panel-fold-reflow.test.ts` 逐帧采样面板的宽度、左缘与外距（三者都保持到那一次切换），并采样抽屉退出全程的 `visibility`（滑动时可见，结束后才隐藏）。
- **一段会话的 agent 有角色，且角色是数据（2026-11-22）。** 每条会话行都带 daemon 给出的 `agentRole: { id, name? }`：工作台主会话是 `coder`，任务子代理保留自己的定义名（`sessionInfo.agentName`，如 `sonic`），顾问记录是 `advisor`，角色功能之前留下的历史会话（或没有任何身份事实的行）回退 `coder`。`id` 是契约——它驱动 `data-agent-role`，也保证未知通道不会消失；可读标签由客户端本地化（`Coder`/`编码`、`Subagent`/`子代理`、`Advisor`/`顾问`），子代理自己的定义名就是它的名称。胶囊显示名称加角色标签，Agent 标签页的身份头把角色标签放在名称下方，两者都不会把子代理或顾问误标成工作台的 coder。后续的新通道（例如 bot）只需在 daemon 侧加一个 id；客户端遇到没有译名的 id 会照原样渲染，而不是丢掉这份身份。
- **会话输入框不再携带模型 / 思考 chip。** 附件、模式、审批、麦克风、专注与发送保留；欢迎页输入框保留自己的 chip，因为新会话还没有胶囊可以打开这个标签页。右侧面板里的侧会话同样保留：`session.agent` 只寻址活动会话，侧会话没有胶囊，因此通过 `keepModelChip` 让 `SessionComposer` 继续渲染 chip，保留模型选择；思考等级仍在 Agent 标签页调整，侧会话不提供该控件。
- **吸附，不淡出。** 胶囊属于界面外壳：滚动时只有消息在它下面移动，药丸的位置与不透明度都不变。实时状态在任何滚动位置都值得读，淡出会在读长回答时刚好把 agent 藏起来。专注模式连整行头部一起隐藏——那里转录本身也隐藏。
- **用户头像就是账户入口。** 左栏原本的设置齿轮、快捷键按钮与远程访问按钮合并成左下角的一个控件：`UserAccountButton`（`AppRail.tsx`）沿用聊天气泡那套三来源头像（GitHub 照片 → 像素脸 → 首字母，以及 `punk`、`initial`），加一枚连接状态点，点开菜单只管账户与应用本身：设置、快捷键、远程访问与断开（未连接时不可点）。原本挤在这里的三行各有唯一归属，因为两个相邻浮层用略有差异的列表重复同一件事，读起来像同一个问题有两个答案：**分享当前会话**属于会话标题菜单（它知道当前会话，而这个入口必须在没有会话时也能用），**切换主机**属于同一 rail 底部的实例控件（它已经列出每台主机与实时状态），**实例管理**属于那个控件的 `InstanceManagerDialog`（它同时管两条轴——守护进程跑在哪、文件在哪），而不是另一个只管端点的管理器。左栏不再有设置齿轮；侧栏底栏（桌面应用之外仍会渲染它的宿主）挂同一个控件，两处都只经一个入口到达设置。⌘, 快捷键与欢迎页/无会话形态也仍能到设置与工作区远程访问。
