# MusePi i18n 架构
[English](i18n.md) | 中文

> **活文档**(2026-08-16 建立)——覆盖仓库内两套独立 i18n 系统:**渲染端**(guest-client,GUI/托盘/协作 Web)与 **TUI**(coding-agent)。词表已于 2026-08-16 拆分为按域模块,en 侧编译级 parity,并提供插件注册 seam。实现为准。

## 两套系统

| | guest-client(`packages/client-core/src/i18n`) | coding-agent(`packages/coding-agent/src/i18n`) |
|---|---|---|
| 消费方 | GUI 主窗/托盘/气泡、collab Web UI | TUI、daemon(复用同模块) |
| 占位符 | **命名参数** `{count}`(模板字面量类型提取校验) | **位置参数** `{0}`(历史约定,未迁移) |
| key 类型 | `TranslationKey = keyof typeof zhCN` 严格(拼错/漏参数编译报错) | 宽松(`key: string`);迁移后的特征命名空间有 zh key 集与 en parity |
| en 映射 | 有(en-US/ 域文件,编译级 parity) | 特征命名空间模块有 en parity;旧词表仍英文 passthrough |
| 词表 | 12 域 + 特征命名空间(`zh-CN/` + `en-US/`) | 13 域 + 特征命名空间(`zh-CN/` + `en-US/`) |
| 插件 seam | `registerTranslations(locale, map)` + `tLoose(key, params)` | `registerTranslations(locale, map)` |

共同约定:未迁移文案仍以英文原文为 key;已迁移功能各自拥有特征命名空间模块,由 zh 词典定义 key 集、en 词典编译期对齐。`t()` 未命中回退到 key 本身,且只在渲染/调用时执行,不在模块加载期。

## 词表拆分(guest-client)

- 域模块:`zh-CN/{shell,composer,sessions,context,collab,transcript,settings,agents,tools,pet,guest}.ts`(每域导出 `XxxKey = keyof typeof x`),`en-US/` 同构。
- barrel(`zh-CN/index.ts` / `en-US/index.ts`)合并为扁平 map,**模块加载时跨域重复 key 抛错**(spread 静默覆盖的替代);TUI 的 `zh-CN/index.ts` 同款守卫。
- **en 编译级 parity**:每个 en 域文件 `export const x = { … } as const satisfies Record<ZhKey, string>` —— en 缺/多 key 是编译错误(负向验证:shell.ts 注入额外 key → TS2353)。比测试更强,新增 zh key 必须同步加 en。
- 测试:`guest-client/src/i18n/i18n.test.ts`(key 集 parity、跨域重复守卫、注册覆盖/隔离、新 locale)+ `guest-client/test/i18n.test.ts`(查找/替换/回退/passthrough/无位置参数残留)。测试内 `setLocale` 必须 `afterAll` 恢复初始值(bun test 同进程顺序执行)。

### 特征命名空间(dsh 组织形式)

被触碰的功能把文案从扁平域文件移入独立的特征命名空间模块,对应 dsh 的 `locale/settings.ts` 形式:

- `zh-CN/settings-compaction.ts` 导出词典与 `SettingsCompactionKey = keyof typeof …`,是 key 集的唯一来源。
- `en-US/settings-compaction.ts` 用 `satisfies Record<SettingsCompactionKey, string>`,en 缺 key 或多 key 都是编译错误。
- 两个 barrel 把模块 spread 进 `t()` 解析的扁平 map,模块加载期的跨域重复守卫同样覆盖它。
- key 是稳定的语义路径(`settings.compaction.threshold.title`、`.desc`、`.option.default`),不再用英文句子当 key。
- schema 驱动的设置把 key 直接写进 `ui.label`、`ui.description`、`ui.group` 与选项文案;GUI 与 TUI 都通过 `t()` 解析。未迁移的行在该功能被触碰前仍保留英文原文。
- `verify-schema-labels-i18n.ts` 同时接受两种形式,因为它逐条在两份 zh 词典里查这个字符串。

迁移规则:改到某个设置时,把它的文案移入所属特征命名空间,不要再新增英文原文 key。压缩设置是本次的参考迁移。

## 插件 seam

- `registerTranslations(locale, map)`:运行时注册/覆盖某 locale 文案。guest-client 版触发 `emit()` 让 UI 即时重渲染;TUI 版无订阅者,`t()` 每次调用读注册表,天然即时。均不持久化(重启恢复核心词表)。
- `tLoose(key, params)`(仅 guest-client):插件自有、不在核心词表的 key 用它(核心 `t` 只收 `TranslationKey`;TUI 的 `t` 本就不限 key)。
- 支持全新 locale(如插件注册 `fr-FR`);该 locale 未注册的 key 回退到 key 原文。

### 插件显示文案(清单数据,不是 key)

插件自己的**名称与说明**不是界面 key,而是包数据,所以它带着一份 `LocalizedPluginText` 映射(`{ en, [locale] }`)下发,**由每个读取方按自己的语言挑**:GUI 走 `extensionDisplayName()`(`apps/desktop/src/lib/slot-host.tsx`),TUI 在 `extension-list.ts` / `inspector-panel.ts` 里读 `getLocale()`。

- 包在 `package.json` 同级带 `locale/<tag>.json`:`{ "meta": { "title": "…", "description": "…" } }`。**文件名即语言标签**(`zh-CN.json`、`ja.json`)。
- `musepi.label` / `musepi.description` 仍是 `en` 兜底(相当于 dsh 的 `package.json` `name`):没有 locale 文件的包维持现在的单句文案,所以采用这套是增量的。
- daemon 从不挑语言——它只下发映射(`displayNameI18n` / `descriptionI18n`),一份快照同时服务中文 TUI 与英文 GUI。
- 解析顺序:完整标签 → 主语言子标签 → `en` → 调用方兜底。匹配大小写无关(文件名保留作者写法);实现见 `packages/wire/src/plugin-config.ts` 的 `resolveLocalizedText()`。

### `ctx.setLabel` 是什么(以及为什么不翻译)

一个插件有三个名字,各管一件事:

| 名字 | 归属 | 读取方 | 语言 |
| --- | --- | --- | --- |
| `musepi.label` | 包清单 | **模型**看到的扩展清单(`prompts/system/extensions-inventory.md`,order 25)、旧的 `plugins.list`、以及 `en` 兜底 | 单一,英文 |
| `locale/<tag>.json` | 包目录 | 每个**界面**:扩展中心、能力中心诊断页、信息卡插件列表、TUI 列表与详情 | 跟随界面语言 |
| `ctx.setLabel(...)` | 运行时调用 | 覆盖清单名字——给需要在装载时自己取名的插件 | 单一 |

`setLabel` 不是界面文案。它的消费者是每个会话只组合一次的提示词区块:名字跟着界面语言变,会让一个显示开关改写提示词并冲掉提示词缓存——而同一个会话可以同时被中文 TUI 和英文 GUI 看着。所以第一方插件只在清单里声明一次名字,装载器从那里初始化 `Extension.label`(`plugin-manifest.ts` 的 `readExtensionPluginLabel`),`test/extension-label.test.ts` 会在内置插件冒出第二处声明时失败。

## 维护指引

1. **改文案**:按功能找对应域或特征命名空间(settings 2137 键最大,其次 tools/pet),不要加回单文件。
2. **加 key**:已迁移功能加到各自特征命名空间(先 zh,同一改动内补 en);旧行加 zh 域 key 并同步 en 域。特征命名空间的 key 是语义路径;旧 key 仍保持英文原文风格。命名参数用 `{name}`,不用 `{0}`。
3. **域间不重复 key**:重复会在 barrel 加载时抛错(报出两个域名)。
4. **GUI 动态 key**(schema 驱动 label、运行时错误串、`tag.${…}` 拼接):显式 `as TranslationKey`;插件/扩展文案走 `registerTranslations` + `tLoose`。
5. **TUI**:`{0}` 位置参数不动;新增域模块时同步更新 `zh-CN/index.ts` 的 import/spread/守卫 parts。
