## 实机复核步骤

1. `bun scripts/dev-smoke.ts -- bun run dev`（隔离 agent dir 的桌面 smoke，勿直连生产 daemon）。
2. 欢迎页 mode chip 选「设计」→ 模式页展开：顶部 8 chip（默认「原型」选中），中央输入框，无「项目名」「工作目录」底栏。
3. 依次点各 chip：placeholder 文案随类型变化；切「模板」→ 内容区变模板 rail。
4. 在「视频」chip 输入描述并发送 → 建出 design 会话且首轮消息发出；会话头 projectMetadata 的 `kind:"media"`、`media.kind:"video"`。
5. Escape 收合回欢迎页；再进「设计」→ chip 选择与草稿保留。
6. 附件：拖文件进输入框发送，确认落盘路径前缀进首轮消息（uploadFirstMessageFiles 通道）。
7. 设置里开关「减少动效」(`gui-motion-off`)：展开/收合无动画。

## 遗留风险 / 待验收方裁决

1. **模板 rail 的 Blank 首位**：委托单把「Blank 首位」列入不动机制，但 codebuddy 的新 rail 没有 Blank 卡（点行即建，无选中态）。模式页里没有"表单"可供 Blank 重置，Blank 语义只能解释为"用默认 metadata 建会话"——是否补一张 Blank 卡由验收方按设计稿裁决，我未自创方案。
2. **`if (!mounted || !rpc) return null`**：codebuddy 给早退加了 `!rpc`（内嵌 composer 要求 rpc 非空）。rpc 为 null 时面板不渲染，与旧行为（渲染但列表为空）略有差异；欢迎页本身依赖 daemon，实际影响极小。
3. **媒体 chip 的 provider 自动选择**：M3.2 的"自动选首个已配置 provider"逻辑随表单删除；chip 路径 metadata 的 media.provider 为 null（默认值列），与 M3.2 表单默认值一致，符合 3.7a"字段全取默认列"的要求；provider 内联选择属 3.7c。
4. **实机未跑**：本轮只做了组件级测试与静态门禁，未启动桌面应用实机点验（步骤见上）。
5. 提示词模板内置条目（PROMPT_TEMPLATES 四条）与媒体子面控件随 3.7a 表单一并删除；3.7c 高级折叠若需要可自 M3.2（commit 8bf66d2ff）找回。
