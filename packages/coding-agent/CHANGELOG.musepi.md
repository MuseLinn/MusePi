## [0.4.26] - 2026-09-12

### Added

- **TUI `/pair` 命令:一条指令把手机端绑到这台机器**:绑定手机此前只能靠 `/collab lan`——它确实会出二维码,但语义是「分享会话」,找「怎么绑定 app」的人无从下手。新增 `/pair`:已在分享则直接出码,未分享则先起局域网分享再出码,并列出各网卡可达地址与「本机浏览器打开」提示;复用既有链接格式与终端 ANSI 二维码组件,手机端扫码即绑(或改用粘贴链接)。`/collab lan|tunnel` 的启动与展示逻辑同时抽成共享函数,两条命令不再各写一份。
  - EN: New TUI `/pair` command — one command to bind the mobile app to this machine. Pairing previously meant knowing that `/collab lan` was the QR path, which reads as session *sharing*, not device pairing. `/pair` shows the code immediately when a share is already running and starts the LAN share first when it is not, listing every reachable NIC address plus the host-machine browser link; it reuses the existing link format and the terminal ANSI QR component, so the phone scans and is bound (or pastes the link instead). The LAN/tunnel start-and-present logic is now shared with `/collab` rather than written twice.

### Fixed

- **修复侧面板内置浏览器空白(页面明明已加载却一片空白)**:两个独立缺陷指向同一表象。(1) **投影被当作过期丢弃**——渲染器的布局版本号是**模块级计数器,页面每次重载即归零**,而主进程的「过期版本」水位线**跨重载存活**(主进程不重载),于是重载后渲染器发出的每一次投影都低于水位线、被静默丢弃,原生视图永远拿不到 bounds 也永远不显示,面板只剩白色底;这正是「重载一下就空白」的成因,也解释了为何视图一直停在创建默认的 800×600。(2) **遮挡判定把「存在」当成「盖住」**——原生 `WebContentsView` 恒在 DOM 之上,所以有浮层盖住槽位时必须隐藏它;但旧判定只问「文档里是否存在可见的 dialog/menu/listbox」,从不管它是否真的盖住槽位,而转录区常驻的回合导航带(24px `role="listbox"`)就紧贴面板左侧几像素,于是任何有回合的会话都会永久隐藏视图。现渲染器给每次投影盖上**页面加载 epoch**,主进程见到新 epoch 即重置水位线;遮挡判定改为**三条件**(`lib/overlay-block`:在屏 + 矩形与槽位相交 + 在该点拥有最上层——只看几何仍会把「与槽位重叠但画在面板下面」的元素误判成遮挡),并带回归测试。
  - EN: Fixed the side panel's built-in browser sitting blank with the page fully loaded — two independent defects produce that one symptom. (1) **Projections were dropped as stale**: the renderer's layout counter is module-scoped and restarts at 0 on every page load, while the main process's "stale revision" watermark survives reloads (main is not reloaded). Every projection after a reload therefore compared below the watermark and was silently discarded, so the native view never received bounds and never appeared, leaving the pane on its white backing — which is why a reload reliably produced a blank pane, and why the view stayed at its 800×600 creation default. (2) **Occlusion treated "present" as "covering"**: the page is a `WebContentsView` that always paints above the DOM, so a real overlay over the slot must hide it — but the old check only asked whether *any* visible dialog/menu/listbox existed in the document, never whether it covered the slot, and the transcript's permanently-mounted turn rail (24px `role="listbox"`) sits a few pixels left of the panel, so every session with turns hid the view for good. Each projection now carries a **page-load epoch** that lets main reset its watermark, and occlusion now requires all three of on screen, intersecting the slot's rect, and owning the paint order at a point inside that intersection — geometry alone still mistook an element that overlaps the slot but paints beneath the panel for an occluder (`lib/overlay-block`), with a regression test.
- **配对码在有效期内可无限复用**:配对码展示在屏幕上,而解析成功后服务端并未删码 —— 10 分钟窗口内同一串数字可反复换取会话链接(拍下屏幕即可长期使用)。现改为**单次有效**:解析成功即作废,TTL 只约束从未被使用的码。该规则抽成可测的 `collab/pair-codes.ts`(单次性/过期/清除共 7 个用例)。
  - EN: Fixed pair codes being replayable for their whole lifetime. The codes are shown on screen, and resolving one did not delete it — the same six digits kept trading for the session link for the full 10-minute window (photograph the screen and keep using it). Codes are now single-use: resolving spends them, and the TTL only bounds codes that were never used. The rule lives in a testable `collab/pair-codes.ts` (7 cases: single-use, expiry, clearing).
- **协作面板:配对码无有效期、拿不到只读链接、也看不出谁在看**:面板丢弃了服务端随码返回的有效期(既无倒计时,也看不出码已失效);只读链接虽由服务端一并下发却从未渲染,只读分享成了 TUI 独占能力;`collab.status` 不含参与者,面板无法区分「空转的分享」与「已有人连上」。现配对码显示倒计时与「单次有效」提示、失效后提示重新获取;新增「复制只读链接」;新增在线参与者列表并标注仅观看者。另修「刷新二维码」名不副实(它只是重取状态、并不重铸链接),现改名为「刷新」。
  - EN: Fixed the share panel showing no pair-code lifetime, offering no watch-only link, and giving no sign of who is connected. It discarded the expiry the daemon returns with each code (no countdown, no indication a code had died); the view-only link was delivered but never rendered, making read-only sharing a TUI-only capability; and `collab.status` carried no participants, so an idle share looked identical to one with a guest attached. The pair code now shows a countdown with a single-use hint and says to mint a new one once it expires; a "copy watch-only link" action is available; and connected participants are listed with watch-only guests marked. The misleading "refresh QR code" button (it only re-read status, never re-minted the link) is now simply "refresh".
- **修复历史消息与切换会话时也「逐字重播」**:揭示引擎把「挂载」当成「有积压」——揭示位置从 0 起算,于是历史消息、切换会话后重新挂载的实时消息都被整段重新打字,收尾的定速排水又把已读内容当成待揭示积压再走一遍。现挂载即定位到该块文本末尾(只有挂载**之后**新增的文本参与动画),`resetKey` 也只在键真正变化时重置(此前 effect 首次运行就重置,等于抵消挂载规则);预览循环仍可从 0 重播。
  - EN: Fixed committed messages and session switches re-typing themselves: the reveal engine treated mounting as backlog — the reveal position started at 0, so a history message (or a live one re-mounted by a session switch) was re-typed in full, and the settle drain then treated the already-read text as backlog and replayed it. Mounting now starts at the end of the block's text (only text that grows *after* mount animates), and `resetKey` only restarts on a real key change (the effect's first run used to reset, which cancelled the mount rule); preview loops still replay from 0.
- **修复流式期间 markdown 不成形(头段现随流增长)**:此前只有**首帧**文本里最后一个 `\n\n` 平衡边界之前的块被解析成 markdown,该边界在冻结后永不再推进——一条长消息只有开头几段是 markdown,其余全程以纯文本滚动,直到流结束才整体成形(这正是「参考 dsh 后怎么没有生效」的实际形态)。现逐帧把新成立的平衡块提升进 markdown 头段:段落、列表、闭合的代码围栏在流式过程中即成形;最后一个平衡边界之后仍是原始文本——逐字 span 动效需要一个稳定的纯文本节点,「未闭合围栏保持字面量」也是同一原因。切点前移沿用 DOM 侧既有的「清空并重挂当前尾段」路径,已显示的字符不会被重新动画。
  - EN: Fixed markdown not taking shape while a message streams (the head now grows with the stream): only the blocks before the last balanced `\n\n` boundary of the *first* frame were parsed as markdown, and that boundary never advanced once frozen — so a long message showed markdown for its opening paragraphs and plain text for everything after them until settle. Every block that becomes complete is now promoted into the markdown head per frame: paragraphs, lists, and a code fence the moment it closes take shape while streaming, while the region after the last balanced boundary stays raw text (the per-character span effects need a stable plain node, which is also why an unclosed fence stays literal). The advancing cut reuses the DOM pass's existing "clear and re-append the current tail" path, so already-shown characters are not re-animated.
- **修复右侧面板拖宽「拖完回弹 + 一路选中文字」**:释放时的吸附读的是 **pointerdown 那次 render 的闭包 `width`**,拖到哪儿松手都会吸回起点附近的档位;吸附又**没有距离阈值**,260–300 全落 300、1200 落 800,精确宽度根本不可达;拖拽期间既不加 `body.gui-resizing`(文本选择冻结与宽度过渡逃逸都挂在它上面——而右面板那条走 `startResize("right")` 的分支**全仓没有调用方**,是死代码),也没有 pointer capture / `preventDefault`,指针一离开 4px 手柄,拖拽就变成扫过转录区选文字。现改用仓内统一的 `usePointerDrag`(capture + 过阈值后 `preventDefault` + pointerId 过滤),起止宽度都走 ref(不再读闭包),吸附补 24px 半径(超出即保留精确值),拖拽期间加 `body.gui-resizing`,并删掉 `startResize` 的死分支。
  - EN: Fixed right-panel width dragging snapping back on release and selecting text along the way: the release-time snap read the `width` captured by the **pointerdown render's closure**, so a drag anywhere snapped to a point near where it began; the snap also had **no distance threshold** (260–300 all landed on 300, 1200 on 800), making an exact width unreachable; and the drag never added `body.gui-resizing` (the class that freezes text selection and escapes the pane's width transition — the right-panel path went through `startResize("right")`, a branch with **no caller anywhere in the repo**), nor used pointer capture / `preventDefault`, so once the pointer left the 4px handle the gesture became a text selection sweep across the transcript. It now uses the repo's `usePointerDrag` (capture + `preventDefault` past the threshold + pointerId filtering), keeps both endpoints in refs (no closure read), snaps only within 24px (otherwise the exact width wins), adds `body.gui-resizing` for the duration, and the dead `startResize` branch is gone.
- **托管浏览器改用 DOM 内的 `<webview>`(消除「原生视图恒在 DOM 之上」的一整类规避)**:右侧面板的页面此前是主进程的 `WebContentsView`,它永远画在 DOM 之上,于是浮层只能靠「让位」或「隐藏页面」凑合——4px 拖拽手柄被吃掉约 3px、rail 悬浮提示被页面盖住(还得再加一条「有提示就隐藏页面」的规避)、菜单与弹窗同理。现页面改为渲染端持有的 `<webview>`(OOPIF,参与 DOM 层叠):手柄、提示、菜单、弹窗全部按普通 z-index 正常显示,`lib/overlay-block.ts` 遮挡判定、4px inset 与整套投影/重投影机制一并删除。主进程保留不可替代的部分——分区权限拒绝与 `omp-file://` 预览、9230 上的 CDP 桥(agent 的 `browser.gui` 照旧用 `puppeteer.connect` 驱动**同一批页面**)、活动台账与风险导航同意门——并新增渲染端↔主进程的 guest 生命周期握手(`guest-ready`/`guest-gone`/`active-tab`/`visibility` ↔ `create-tab`/`select-tab`/`close-tab`,建标签带 15s 超时与明确失败回包)。已用隔离 harness(Electron 43 + 真实控制器 + 真实分区 + 真实桥)实测:`/json/version` 与 `Target.*`、`Page.navigate`、`Runtime.evaluate`、`Page.captureScreenshot` 全通,浮层在页面上方赢得命中测试,agent 建标签 266ms 完成绑定。两条实测约束已写进代码与文档:① `<webview>` 一旦在 DOM 中被移动就**销毁 guest**,故元素挂在常驻宿主、永不移动/永不卸载(标签切换只切 `opacity`);② `display:none`/移出视口/零尺寸下 `capturePage()` 永不返回,故隐藏只用 `opacity`(面板关闭时宿主仍保留合成表面,agent 仍可截图),截图另有 1.5s×2 有界重试。**语义变化**:渲染进程重载(dev 热重载、窗口重载)会销毁全部 guest(此前由主进程持有、不受重载影响),标签 URL 现持久化在 localStorage 以便恢复。
  - EN: The right-pane browser is now a DOM `<webview>`, removing a whole class of "native view always above the DOM" workarounds. The page used to be a main-process `WebContentsView` that permanently painted over the DOM, so overlays had to either yield or hide the page: the 4px width handle lost ~3px to it, the rail's tooltips were buried and needed a "hide the page while a tooltip shows" rule, and menus/popups had the same problem. The page is now a renderer-owned `<webview>` (OOPIF, part of DOM stacking): the handle, tooltips, menus and dialogs all layer normally, and `lib/overlay-block.ts`, the 4px inset and the whole projection/re-projection machinery are deleted. Main keeps what only it can own — the partition's deny-all permissions and `omp-file://` previews, the CDP bridge on 9230 (the agent's `browser.gui` still drives the SAME pages through `puppeteer.connect`), the activity ledger and the risky-navigation consent gate — plus a new guest lifecycle handshake (`guest-ready`/`guest-gone`/`active-tab`/`visibility` ↔ `create-tab`/`select-tab`/`close-tab`, tab creation with a 15s deadline and an explicit error reply). Verified with an isolated harness (Electron 43 + the real controller + the real partition + the real bridge): `/json/version` and `Target.*`, `Page.navigate`, `Runtime.evaluate` and `Page.captureScreenshot` all work, an overlay wins hit-testing above the page, and an agent-created tab binds in 266ms. Two measured constraints are documented in the code: (1) moving a `<webview>` in the DOM **destroys its guest**, so elements live in an always-mounted host and are never moved or unmounted (tab switching only toggles `opacity`); (2) `capturePage()` never settles while the guest is `display:none`, off-viewport or zero-sized, so hiding is `opacity`-only (a closed panel keeps the composited surface, so the agent can still screenshot) and capture retries once within a 1.5s cap. **Behaviour change**: a renderer reload (dev hot-reload, window reload) now destroys every guest (main used to own them, so reloads were invisible); tab URLs are persisted to localStorage so the tabs come back.
- **修复托管浏览器迁移后的四个实测问题**:① **空白标签的起始页点不动**——宿主隐藏(`opacity:0`)时外层虽是 `pointer-events:none`,但标签层写的是「激活即 auto」,而子级的 `auto` 会在 `none` 父级内部**重新开启命中测试**,透明 guest 于是继续吃掉本属于起始页的点击(现改为 `visible && active` 才 `auto`)。② **网页显示尺寸/位置不对**(看起来变大并被裁、点击坐标整体错位)——宿主的 rect 只在**尺寸**变化(ResizeObserver)与 window resize/scroll 时更新,而侧栏折叠、面板宽度拖动、视图切换这类**纯位移**不触发其中任何一个,宿主便停在旧 rect;现补 200ms 低频复测 + `transitionend`,并让 `setPaneRect` 对相同 rect 直接返回(避免每秒数次无谓重渲染)。③ **`ERR_ABORTED (-3)` 红条**——根因是 `<webview src>` 被绑到**会被导航更新的 state**:guest 报回新 URL → React 重设 `src` → guest 重载并顶掉在途加载(隔离 harness 实测:被顶掉的加载正是以 `ERR_ABORTED (-3) loading '<url>'` reject,与截图里的字串一致)。现 `src` 只在元素创建时给一次(`entrySrc` 契约 + 回归测试),后续导航只走 `loadURL`;同时主进程把「被顶掉」的 ERR_ABORTED 视作非失败(页面确实正在加载),不再冒红条。④ **轨迹/转录跳转把整个界面顶上去并被遮挡**——两处都用 `scrollIntoView({block:"start"})`,它会**连带滚动所有可滚动祖先**(整个壳上移),落点又贴着容器上沿;现改为只滚自己的滚动容器、按容器坐标算落点并留 12px 顶部内缩。
  - EN: Fixed four issues found in the `<webview>` migration. (1) **The blank tab's start page was unclickable**: with the host hidden (`opacity: 0`) the outer layer is `pointer-events: none`, but the per-tab layer said "auto when active" — a child's `auto` **re-enables hit-testing inside a `none` parent**, so the transparent guest kept eating the clicks meant for the start page (now `auto` needs `visible && active`). (2) **The page rendered at the wrong size/position** (looked oversized, clipped, and clicks landed off-target): the host's rect was only re-measured on **size** changes (ResizeObserver) plus window resize/scroll, while position-only shifts (sidebar collapse, panel drag, view switching) trigger none of them, leaving the host on a stale rect — it now re-measures on a 200ms interval (and `transitionend`), and `setPaneRect` returns early for an unchanged rect so the interval costs no re-renders. (3) **The `ERR_ABORTED (-3)` banner**: `<webview src>` was bound to state that navigation itself updates, so the guest's reported URL re-pointed the element, reloading it and aborting the in-flight load (the isolated harness reproduces exactly the `ERR_ABORTED (-3) loading '<url>'` string from the report). `src` is now set once at element creation (`entrySrc` contract + regression test) and later navigations only use `loadURL`; main also treats an aborted-by-supersede load as "still loading" instead of an error. (4) **Trajectory/transcript jumps pushed the whole shell up and left the target half-hidden**: both used `scrollIntoView({ block: "start" })`, which scrolls **every** scrollable ancestor, and landed the row flush against the scroller's edge — each now scrolls only its own scroller, computed in that scroller's coordinates with a 12px top inset.
- **托管浏览器补齐参考实现(openchamber)的三处行为**:① **视口预设此前形同虚设**——预设只用 `max-width` 约束槽位,flex 一收缩就退回面板宽度,预设比面板宽时既不缩放也不裁切(「网页显示尺寸不正常」的另一半成因)。现按 openchamber `fitViewport` 的做法:页面**按预设宽度布局**(响应式检查才有意义),再整体按 `scale = min(1, 可用宽/预设宽)` 缩放居中(`lib/browser-viewport.ts` 纯函数 + 4 用例,缩放只向下不向上);② **最大化面板时页面被埋**——宿主 `z-index: 5` 低于最大化面板的 850,现提到 900(高于面板、低于应用的弹层与提示);③ **真实加载失败没有任何提示**——`did-fail-load` 只把 loading 置 false。现补错误面:仅主帧失败才报、忽略 `ERR_ABORTED (-3)`(导航被顶掉不算失败),错误描述 + 失败 URL 显示在既有错误行,成功加载后自动清除。
  - EN: Three behaviours brought in line with the reference implementation (openchamber). (1) **Viewport presets did nothing**: a preset only set `max-width` on the slot, so flex shrank it back to the panel width — a preset wider than the panel was neither scaled nor cropped (the other half of "the page renders at the wrong size"). Following openchamber's `fitViewport`, the page now **lays out at the preset width** (which is what makes a responsive check meaningful) and is scaled to fit with `scale = min(1, available / preset)`, centred — a pure helper (`lib/browser-viewport.ts`) with four cases, and it never scales up. (2) **A maximized panel buried the page**: the host sat at `z-index: 5`, below the maximized panel's 850 — it is now 900 (above the panel, below the app's dialogs and tooltips). (3) **A real load failure said nothing**: `did-fail-load` only cleared the loading flag. There is now an error face — main-frame failures only, `ERR_ABORTED (-3)` ignored (a superseded navigation is not a failure), with the description and failing URL in the existing error row, cleared by the next successful load.
- **右面板拖宽不再压扁主视图 + 输入框底栏窄宽度不再重叠**:① 面板宽度此前只钳 260–1200、与窗口无关,拖到 1200 可把会话列挤成一字一行、组合器无处安放。现按窗口算预算:拖拽起点量出「面板右缘 − 会话列左缘 − 会话列最小宽(420px)」作为上限(这两条边在拖拽期间固定,所以上限稳定),窗口 resize 时重新钳制(持久化宽度也一并收进预算),吸附点同样受上限约束;判定抽成纯函数 `lib/panel-width.ts`(4 用例)。② 输入框底栏(`.gui-composer-row`)是 `space-between` 且**不换行**,两侧按钮又都是固定 26px、不可收缩,窄宽度下直接压在一起;现改为可换行(`flex-wrap` + `row-gap`),右组补 `min-width: 0` 让 chip 截断而非撑宽,并以 `margin-left: auto` 保证换行后仍靠右。
  - EN: The right-panel drag no longer squeezes the main view, and the composer's action row no longer overlaps at narrow widths. (1) The panel width was clamped only to [260, 1200] regardless of the window, so dragging it to 1200 could squeeze the chat column into one word per line with the composer nowhere to go. The budget is now derived from the window: at drag start it measures `panel right edge − chat column left edge − MIN_CHAT_WIDTH (420px)` (both edges are fixed during the drag, so the cap is stable), window resizes re-clamp the width — including the persisted one — and the snap points are clamped by the same budget.
