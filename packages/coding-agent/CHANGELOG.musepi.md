## [Unreleased]

### Fixed

- **画板文字标签：六个字只显示三个、以及拖不动角手柄**：两个独立的真 bug。① 盒宽按「字符数 × 字号 × 0.62」估算，那是拉丁文的平均字宽——汉字步进约 1.0em，要宽约 1.6 倍，于是六个 24px 汉字被「估算」成 89px 而实际占 ~144px，盒子被夹到最小宽度、中文标签只露出前三个字。现在宽度取自**真实画布度量**（`measureTextWidth`，与 Konva 自己量文字用的是同一种操作），中文、英文、混排一律按实际绘制宽度算，一行放不下就换行、盒子向下增高。② 上一轮从手柄的**渲染**条件里删掉了「排除文字」，却漏了 `onPointerDown` 里同一个闸门——手柄画出来了，但按下时命中没有登记缩放状态，拖动成为空操作。两处现已同时移除，文字与其他图形走完全相同的缩放/拖动/擦除路径。另外：用户亲手拖出的宽度会被**保留**（文字在里面换行，不再弹回去贴合内容）、文字按字断行（中文没有空格，只按词切分会让整句停在一行）、编辑浮层的字体与画布统一（此前提交瞬间文字会重排），并且在无画布环境下度量会降级而不是抛错。
  - EN: Sketch board text labels: six characters showing only three, and corner handles that would not drag — two independent real bugs. (1) Box width was estimated as `chars × fontSize × 0.62`, a Latin average; a CJK glyph advances ~1.0em, about 1.6× wider, so six 24px 汉字 "measured" 89px while occupying ~144px — the box clamped to its minimum and the label showed only its first three characters. Width now comes from a **real canvas metric** (`measureTextWidth`, the same operation Konva itself measures text with), so CJK, Latin and mixed strings are sized by what actually gets painted: anything too long wraps and the box grows downward. (2) The previous pass removed the text exclusion from the handles' **render** condition but missed the identical gate in `onPointerDown` — the handles drew, but the press never registered scale state, so dragging was a no-op. Both are gone now, and text resizes/drags/erases through exactly the path shapes use. Also: a width the user dragged is **kept** (text wraps inside it instead of the box springing back to fit its content), text wraps per glyph (CJK has no spaces, so a word-only splitter left a whole Chinese sentence on one line), the editing overlay shares the canvas font (committing used to visibly reflow the text), and measurement degrades instead of throwing where no canvas exists.

- **画板文字标签随文本自动换行增高，且与其他图形一样可缩放**：旧实现里文字只存一个锚点，宽度每次渲染都用「字符数 × 字号 × 0.62」重算，于是一整句话永远是单行、直接冲出画板、高度永不增长；同时缩放手柄层显式排除文字，导致它是画板上唯一拖不动也缩放不了的对象。现在文字与其他对象**共用同一套对象模型**：标签持有真实矩形（`[x,y,w,h]`），输入时按词换行、高度跟着行数长，宽度回缩到最宽一行（上限是用户拖出的盒宽）；选中后出现与矩形/图片相同的四角手柄，缩放、拖动、擦除全走同一条代码路径；单击＝选中并拖动，**双击**才进入编辑（过去单击即打开插入符，正是它让文字拖不动）。编辑浮层自身也随输入换行增高。存量画板里只有两个数字的旧标签打开时自动升级成盒子，不会错位或丢失。
  - EN: Sketch board text labels now wrap, grow and resize like every other shape. The old label stored a bare anchor and re-derived its width from `charCount × fontSize × 0.62` on every render, so a whole sentence stayed a single line, ran off the board and never grew taller; the scale-handle layer also excluded text outright, making it the one object on the board you could neither drag nor resize. Text now shares the **same object model** as everything else: a label owns a real rectangle (`[x, y, w, h]`), wraps by word as you type, grows taller with its line count and retracts in width to the widest line (capped at the box you dragged), and once selected it shows the same four corner handles as a rect or an image — resize, drag and erase all run down one code path. A single click selects and drags, and **double-click** enters editing (the old single-click caret was exactly what made labels immovable). The editing overlay itself wraps and grows with the text too. Existing boards whose labels hold only two numbers are upgraded to a box on open, so nothing shifts or goes missing.

- **画板：点击画板图重新打开的是原画（A0），不再是粘贴一张导出图（A1）**：此前完成只导出一张 PNG，点回 chip 时又把那张 PNG 当底图挂进画板——每一笔、每个图形和文字全部融成一张位图，再编辑只能在图上涂，任何一处旧细节都改不回来。现在完成同时交出画板的**笔画列表**（`lib/sketch-scene.ts` 的 scene），composer 把它挂在 chip 上：点击 chip 恢复的是对象本身，每一笔依旧可选、可拖、可缩放、可擦除，改哪一处就改哪一处；再次完成是像素与 scene **一起**替换，来回编辑多少次都不退化。恢复出来的内容是画板的开场状态（不进撤销栈、不算未保存改动），笔画 id 从恢复集之后续号以免命中错对象；换窗口尺寸后重开会等比缩放回去（压力值不动，线宽随同一系数）。草稿里也尽量带上 scene（超容量或含导入图片时只丢 scene、保住附件），缺失时回落成旧的整图打开，不会退化成打不开。
  - EN: Sketch board: clicking a board image reopens the original drawing (A0) instead of pasting the exported copy (A1). Finishing used to emit only a PNG, and clicking the chip mounted that PNG back as the base layer — every pen stroke, shape and label fused into one bitmap, so a re-edit could only paint over the picture and no earlier detail was recoverable. 完成 now also hands over the board's **stroke list** (a `scene`, `lib/sketch-scene.ts`) which the composer stores on the chip: clicking it restores the objects themselves, so each stroke is again selectable, movable, scalable and erasable — you fix exactly the part you meant to. Finishing again swaps pixels **and** scene, so the round trip survives any number of re-edits. Restored content is the board's opening state (not an undo step, not a dirty change), stroke ids continue past the restored set so the eraser and select tool never hit the wrong object, and reopening in a resized window rescales proportionally (pressure untouched, thickness follows the same factor). Drafts carry the scene when it fits (oversized payloads or scenes holding an imported picture drop only the scene and keep the attachment), and a missing scene falls back to the old flat-image reopen rather than refusing to open.

## [0.4.34] - 2026-09-20

### Added

- 桌宠新增**交互反应轴**（戳弄 / 被抓包 / 入睡前）：除会话状态那条轴之外，新增第二条轴专管**用户主动触发的反应**——`startled`（戳一下的惊愕：瞪眼、视线收回正中、刻意不眨眼）、`delighted`（900ms 内补一下的开心：弯眼 + 弹跳）、`curious`（察觉时的偏头，视线明显偏出去）、`dozing`（入睡前的半睁眼，全系统最慢最深的呼吸）、`peek`（"被抓包"的假装没看你）。反应**叠在状态之上**而非常规替换：戳弄绝不写进会话状态、按自己的时钟释放（composer 与桌面桌宠同步），并且期间状态那层的材质（error 的红眼、hover 的增亮辉光）不会被重置——所以球在工作时被戳，仍会一边转圈一边惊一下。身体运动只在戳弄类反应里带过冲入场（全系统唯一允许"闹"的运动），约一秒内自解；同时补齐两个闲时桥段：进入 60s 睡眠闩锁前 40s 开始打瞌睡，以及每 12–26s 一次的偏头/"被抓包"。
  - EN: The pet gains an **interaction reaction axis** (poke / caught-looking / pre-sleep): beyond the session-state axis, a second axis now owns **user-initiated reactions** — `startled` (the gape on a poke: eyes fly wide, gaze snaps to centre, deliberately no blink), `delighted` (a follow-up within 900ms: pleased squint plus a bounce), `curious` (the head-tilt of noticing, gaze parked well off-centre), `dozing` (half-lidded pre-sleep, the slowest and deepest breath in the system), and `peek` (the "caught looking" pretence). Reactions LAYER on top of the mood rather than replacing it: a poke is never written to session state, releases on its own clock (identical on the composer pet and the desktop pet), and the mood's materials (error's red eye, hover's brightened glow) survive underneath — poke the orb while it works and it still startles *and* keeps spinning. The only loud body motion in the system lives on the poke reactions (an overshoot entrance that resolves in about a second); two new idle beats came with it — drowse starting 40s before the 60s sleep latch, and a peek/curious beat every 12–26s.

### Fixed

- **语音输入第二轮：中文出简体、转录全程有反馈、麦克风按钮回归动效**：中文识别输出繁体的根因是内置 whisper-small q8 的中文语料偏台湾侧——两条引擎都没有 decoder prompt 可偏置文字方向，现在解码后统一过 OpenCC 繁→简（新模块 `zh-hans.ts`，懒加载约 1 MB 词典，仅在语言钉住 zh 时生效，加载失败降级原文；TW/HK 用 auto 可保留繁体）。「转录期间毫无反馈、文字凭空出现」的根因是 composer 用两个布尔标志维护听写状态，点停止时双双清零而转录请求才刚开始——整个等待期渲染成空闲；重构为单一相位状态机（`use-dictation.ts`：录音→转写→完成），转写中再点一次是真取消（旧版只清 UI、在途转录结果照样落进输入框），Esc 任意相位取消、卸载自动清理。反馈形态按裁定重做：30px 麦克风胶囊只承载动效（录音脉冲/转写 spinner），秒数、「转写中…」与 Esc 提示移入输入卡内的状态条——13 根纯 CSS 波形（共享 scaleY 关键帧、负延时错相）+ 真实音量只调透明度，整个转录等待期都有活的反馈；会话输入框与欢迎页共用同一状态机。
  - EN: Voice input round two: Simplified zh output, live feedback through the whole transcription, and the mic button back to motion-only. Traditional-Chinese output traces to the bundled whisper-small q8's TW-leaning zh corpus — neither engine exposes a decoder prompt to bias script direction, so decode now funnels through OpenCC t→cn (new `zh-hans.ts`, ~1 MB dictionary lazy-loaded, applied only when the language is pinned to zh, degrading to the original on load failure; TW/HK users on auto keep Traditional). "No feedback while transcribing, text appears from nowhere" traced to the composer's two-boolean dictation flags, both cleared on stop while the transcribe RPC was only starting — the whole wait rendered as idle; replaced with a single-phase state machine (`use-dictation.ts`: recording → transcribing → done), where toggling during transcription truly cancels (the old UI just cleared its flags and let the in-flight result land anyway), Esc cancels from any phase, and unmount cleans up. Feedback rebuilt per direction: the 30px mic capsule carries motion only (recording pulse / transcribing spinner); seconds, "transcribing…" and the Esc hint moved into an in-input status strip — a 13-bar pure-CSS waveform (shared scaleY keyframes, negative-delay stagger) with the real mic level only modulating opacity, so the entire wait has live feedback; the session composer and the welcome composer share the same state machine.

- **微信 Bot 扫码登录的二维码终于显示出来了**：iLink 的 `get_bot_qrcode` 返回的 `qrcode_img_content` 实测是**二维码要编码的内容 URL**（`liteapp.weixin.qq.com` 扫码目标），不是图片——界面此前把这个 URL 原样塞进 `<img src>`，必然 404，这就是「二维码不显示」的直接原因；现在用内置 QR 编码器把该 URL 本地栅格化为 SVG（真图片 URL 与 base64 PNG 两种旧形状仍直通）。配套把轮询协议补齐：`get_qrcode_status` 带上规范的 `iLink-App-ClientVersion` 头；二维码过期自动换新码（GUI 两秒状态轮询直接浮出新码）；扫码后采纳服务端回传的区域 API base（`baseurl`，后续收发走会话自己的 IDC）；登录时生成协议要求的 `X-WECHAT-UIN`（随机 uint32 → base64）；`getupdates` 命中 `errcode -14`（会话过期）自动回落扫码重登，而不是停在「已连接」却永远收不到消息；长轮询补 45s 超时防挂死；开始轮询时按协议发 `notifystart`。
  - EN: The WeChat bot login QR finally renders: iLink's `get_bot_qrcode` returns `qrcode_img_content` as the URL the QR must ENCODE (the `liteapp.weixin.qq.com` scan target), not an image — the UI was stuffing that URL straight into `<img src>`, which 404s; that was the "QR never shows" bug. The URL is now rasterized locally with the built-in QR encoder (crisp SVG; real image URLs and base64 PNGs still pass through). The polling protocol is completed alongside: `get_qrcode_status` carries the spec `iLink-App-ClientVersion` header, an expired QR automatically re-issues (the GUI's 2s status poll floats the fresh code in), a confirmed scan adopts the server's regional API base (`baseurl` — later sends/polls ride the session's own IDC), login generates the protocol's `X-WECHAT-UIN` (random uint32 → base64), a `getupdates` `errcode -14` (session expired) falls back to QR re-login instead of sitting "connected" while silently receiving nothing, the long poll gets a 45s timeout so a hung connection can't wedge the loop, and the poller announces itself via `notifystart` per the spec.

- **模型选择菜单的点击/滚动响应**：列表此前把鼠标高亮挂在每行的 `mousemove` 上——光标每扫过一行就 setState 重渲染整个数百行的菜单（加上每次渲染重算过滤/分区排序与逐行 `flatRows.indexOf` 的 O(n²)），点开菜单就掉帧。现在鼠标高亮交还给 CSS `:hover`（`mousemove` 不再触碰 React 状态），↑↓ 导航独占高亮期间由列表上的 `data-kbd-nav` 抑制行 hover（滚动驱动的 mousemove 也抢不走高亮——防劫持语义保留），首次真实移动让位回 CSS（一次渲染）；过滤/分区/扁平化全部收进单个 `useMemo`，行级 `kbdIndex` 换 O(1) Map 查找，行组件 `memo` 化——键盘导航只重渲染新旧两行。
  - EN: The model picker menu's click/scroll responsiveness: the list hung its pointer highlight on per-row `mousemove` — every row crossing re-rendered the whole multi-hundred-row menu via setState (on top of re-running the filter + section sort and the per-row `flatRows.indexOf` O(n²) each render), so opening the menu stuttered. The pointer highlight now belongs to CSS `:hover` (mousemove never touches React state); while ↑↓ owns the highlight, a `data-kbd-nav` flag on the list suppresses row hover (scroll-fueled mousemove still can't steal the highlight — the anti-hijack semantics survive), and the first real pointer move yields it back with a single render. Filtering/sectioning/flattening live in one `useMemo`, the row's `kbdIndex` is an O(1) Map lookup, and rows are `memo`'d — keyboard navigation re-renders just the two rows whose highlight moved.

- **弹窗与浮动菜单并入液态玻璃家族**：全应用唯一的弹层配方点 `.gui-menu-popup`（指令候选、模型菜单、右键菜单等一切浮动菜单都从这里拿表面）此前还是磨砂毛玻璃——现在与 composer 胶囊同族：`--glass-bg` 玻璃底垫在 scrim 之下（窗口透明开关的内联 100% 仍能把整面压回不透明）、规格棱边（亮顶/暗底）替代旧的两条均匀内亮线、对角水光 sheen 以 `z-index:-1` 钉在背景之上内容之下（popup 的 fixed 定位自带 stacking context，菜单子结构不可控，不需要 `> *` 救援）。`.gui-dialog` 与画板浮层 `.gui-sketch-board` 同步对齐：border 环换成非对称 inset 棱边、blur/saturate 换家族 token（跟随透明度滑杆，默认值不变）。
  - EN: Dialogs and floating menus join the liquid-glass family: the app's single popup recipe point `.gui-menu-popup` (every floating menu — command candidates, the model picker, context menus — takes its surface here) was still plain frosted glass; it now shares the composer pills' material — a `--glass-bg` pane layered UNDER the scrim (the window-transparency toggle's inline 100% still mutes the whole surface opaque), the asymmetric specular rim (bright top / dim bottom) replacing the old two uniform inset lines, and the diagonal sheen pinned via `z-index:-1` above the pane and below every child (the popup's fixed positioning provides the stacking context, so no `> *` rescue is needed with uncontrolled menu children). `.gui-dialog` and the sketch board overlay align the same way: the border ring becomes the asymmetric inset rim, and blur/saturate move to the family tokens (slider-following, identical at default).

- **触发词/命令高亮升级为胶囊徽标，shell 前缀 `!` 纳入高亮**：输入框里的活语法 token（行首 `/` 命令、行首 `!`/`!!` shell 前缀、独立 magic 词）从细金色文字改为**accent 胶囊徽标**，特殊字段与普通文本一眼可分；`!`/`!!`（TUI 同款 shell 前缀）此前完全没有样式，现已按行首规则纳入（胶囊盖住 `!` 与命令头，`! cmd` 同样覆盖）。胶囊**度量中性**：横向 padding 由等量负 margin 偿还，镜像层与 textarea 的字符 advance 仍逐像素一致，光标不偏。语义上刻意保守：`@` 与 `#` 不加胶囊——发送链路里没有任何展开逻辑，胶囊会许诺不存在的行为；一行里第二个及之后的 `/token` 也不加——daemon 只把第一个 token 当命令名、其余是参数（`/security /guided-goal` 执行的是 security，后者是参数），胶囊只给真正会执行的 token。解析器新增 first-wins 去重契约（`!!workflowz` 是 shell 命令而非思考触发词），补 9 例单测覆盖全部边界。材质上胶囊已并入全局液态玻璃家族——共享玻璃底 + 高光棱边 + 对角水光，accent 染色按 armed-state 配方叠在玻璃上（hover/按压态因高亮层 pointer-events none 天然不适用）。
  - EN: In-input live tokens become pill badges, and the shell prefix `!` joins the highlight: line-leading `/` commands, line-leading `!`/`!!` shell prefixes, and standalone magic words now render as accent capsules instead of thin gold text, making special fields instantly distinguishable from plain text. The TUI-style `!`/`!!` shell prefix had no styling at all and now follows the line-leading rule (the pill covers the bang and the command head; `! cmd` is covered too). The pills are **metric-neutral**: horizontal padding is repaid by an equal negative margin, so the mirror layer and the textarea stay pixel-locked and the caret does not drift. Deliberately conservative semantics: `@` and `#` get no pill — nothing in the send path expands them, so a pill would promise behaviour that does not exist; nor does the second `/token` on a line — the daemon takes the first token as the command name and the rest as args (`/security /guided-goal` runs security with the rest as its argument), so only tokens that actually execute get one. The parser gains a first-wins dedupe contract (`!!workflowz` is a shell command, not a thinking trigger) with 9 new unit tests covering the edges. The pills also join the global liquid-glass family — shared glass fill + specular rim + diagonal sheen, with the accent tint layered per the armed-state recipe (hover/press states don't apply — the overlay is pointer-events none).

- **触发词高亮不再带偏光标，历史会话的模式名回归「工作模式」**：输入框里的 `ultrathink` / `workflowz` 等触发词高亮此前用等宽字体加粗渲染——字符宽度与 textarea 的实际字形不一致，镜像高亮层与透明输入层从此错位，光标和可见字符对不上；高亮 span 现在**只承载颜色**（与 TUI 同样的朴素强调），凡会改变字符宽度的属性（字体族/字重/字距/内边距）一律禁入高亮层。侧栏悬浮卡与右栏头部的模式名：守护进程未记录预设的历史会话（modeId 为空）此前回落「默认模式」，现在空 id 直接按默认预设 work 解析（与欢迎页 `modeId ?? "work"` 同一约定），显示「工作模式」；右栏快照缺失时同样不再出现「默认模式」。
  - EN: Trigger-word highlighting no longer skews the caret, and historical sessions get their real mode name back: in-input `ultrathink` / `workflowz` highlights were painted in bold monospace — wider than the textarea's proportional glyphs, so the mirror highlight layer drifted off the transparent input layer and the caret no longer met the visible characters. Highlight spans now carry **colour only** (the same plain emphasis as the TUI); anything that changes glyph advance (font family / weight / letter-spacing / padding) is banned from the highlight layer.
