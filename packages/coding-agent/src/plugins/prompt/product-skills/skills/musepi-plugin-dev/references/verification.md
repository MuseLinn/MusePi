# 在可用环境里验收

验收的强度跟改动的风险走。能跑起来看的就跑起来看；跑不起来就明说什么没验到，不要用别的东西替代。

## 隔离实例

GUI 验收用独立实例，不打扰用户正在用的那个：

```
electron . --remote-debugging-port=9224 --user-data-dir=/tmp/<name>
```

它连的是同一个 daemon，只是渲染进程独立。通过 CDP 驱动：点击、读 DOM、截图。

`MUSEPI_CDP_PORT` 环境变量能让正常启动也开放调试端口，适合配合自动化。

## 能验什么

| 层面 | 手段 |
| --- | --- |
| 类型与格式 | `bun check` |
| 装载 | `plugin_manager` 的 `list_plugins`、`cordis_inspect_self` |
| 工具行为 | 真实会话里调一次工具，看结果 |
| 界面 | 隔离实例 + CDP：座位是否挂载、样式是否用主题令牌、控制台有无报错 |
| 主题 | 明暗两套都看一遍 |

## 界面验收的具体检查

- 座位挂上了，不是静默消失（未挂载的组件在插件详情里显示 partial）。
- 样式只用主题令牌，硬编码颜色在暗色主题下会露出来。
- 控制台没有座位条目崩溃。
- 与相邻的宿主页面并排看，间距、字号、分组没有突兀。

## 不要做的

- 为了截图去找认证令牌、改 `HOME`、翻个人浏览器配置。
- 没有浏览器控制时，用模拟页面截图冒充「已验证」。
- 对纯视觉改动只跑类型检查就报告完成——那是没验，不是验过了。

做不到界面验收时，明确说「界面部分未验证」，并给出已经验到的部分。
