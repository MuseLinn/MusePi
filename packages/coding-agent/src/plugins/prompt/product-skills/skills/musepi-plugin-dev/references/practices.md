# 工程实践与验收

## 写代码

- 先读邻近的同类插件，沿用它的结构，不要引入新的默认写法。
- 逻辑与注册分开：把可测的纯函数放在入口之外，入口只做注册。
- 注册点全部走 `ctx.*`；清理用 `ctx.effect`，不要靠插件卸载时手动收拾。
- 声明式优先：能从清单一眼看出的关系（组件、配置字段、依赖）就写进清单，不要藏在代码里。

## 验证

1. `bun check`（biome + 类型）在包内通过。
2. 有测试就加测试；逻辑抽成纯函数后单测，不要为「看起来有测试」而写空跑。
3. 端到端：用真实会话跑一次工具调用，确认装载、调用、结果、卸载都对。只用导入成功或编译通过作为证据是不够的。

## 报告

- 说「已验证」时，给出跑过的命令与结果；没跑过的不要说成跑过。
- 部分完成要说明剩下什么，不要把一个能编译但没接通的实现报告为完成。
- 环境受限导致的失败与改动引入的失败分开报告。

## 常见错误

| 现象 | 原因 |
| --- | --- |
| 插件装了但工具不出现 | 组件声明了 `entry` 但入口没注册；或者工具被 `defaultInactive` 挡住且不在当前预设的工具环里 |
| 改动后行为没变 | 改的是子模块但入口未重载；或 daemon 侧注册代码需要重启 |
| 装载报错但详情为空 | 清单字段坏了被逐个丢弃；看宿主日志里的结构化原因 |
| 监视器 CPU 打满 | 插件树里出现指向仓库根的符号链接，被 watcher 跟随；依赖应靠重装而非编辑 |
