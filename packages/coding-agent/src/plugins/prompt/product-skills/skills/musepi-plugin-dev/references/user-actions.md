# 让模型也能操作插件的界面

插件界面上能做的事，凡是**改动应用数据或配置**的，都应当同时有工具入口，让模型能替用户完成；纯视图操作（切标签、展开详情）不需要。

## 一个操作，两个调用方

- **界面**：组件里直接调用你自己的 daemon 侧逻辑。
- **模型**：注册一个工具，`run` 走同一条逻辑。

两边调同一个函数，不要各写一份。行为分叉是这类插件最常见的问题：界面上加了一项校验，工具路径忘了加。

## 连接两条路的机制

| 方向 | 机制 |
| --- | --- |
| 界面 → daemon | `ctx.rpc.register(method, handler)`；界面通过 `ext.call` 调用 |
| 需要推送 | `ctx.rpc.webRoute(...)` 挂一条 `/api/<namespace>/` 路由，用事件流代替轮询 |
| 模型 → 你的逻辑 | `ctx.tools.register({ name, parameters, run })` |

`ctx.rpc` 的方法与 `ctx.tools` 的工具共享同一份底层逻辑模块，只是入口不同。

## 工具设计要点

- 工具的**结果**要让模型知道下一步能做什么：改完返回新状态，而不是一句「成功」。
- 有副作用的工具要能取消——`run` 接收的上下文里带取消信号。
- 工具名与界面上的按钮文案对得上，用户说「点那个导出」时模型能找到 `export_...`。

细节见 `tool-design.md`。
