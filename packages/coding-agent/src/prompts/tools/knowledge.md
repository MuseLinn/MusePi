# knowledge — 项目知识（笔记 / 待办 / 计划）

读写**当前项目**长期保留的知识，三条线：

| kind | 是什么 | 何时用 |
|---|---|---|
| `note` | 一段 Markdown 笔记 | 记下结论、约定、踩过的坑 |
| `todo` | 一条可勾选的待办 | 跨会话要跟进的事 |
| `plan` | 一整份 Markdown 计划文档 | 多步骤方案（开头必须是 `# 标题` 行） |

这三样和右侧「项目知识」面板是**同一份数据**：写进去用户立刻能看到，用户在面板里的改动你也读得到。

## 怎么用

```
knowledge { action, kind?, id?, body?, text?, done?, directory?, projectId?, expected? }
```

| action | 必填 | 说明 |
|---|---|---|
| `list` | — | 一次列全：所有笔记、待办、计划（含每个计划的文件路径） |
| `save` | `kind` + 内容 | 新建（不带 id）或替换（带 id） |
| `delete` | `kind` + `id` | 删除一条 |
| `show` | `kind: "plan"` + `id` | **在界面上打开**给用户看，同时返回正文 |

`save` 的字段按 kind 取：

- `kind: "note"` → `body`（笔记正文）
- `kind: "todo"` → 新建给 `text`；改已有给 `id`，`done` 可单独发送（只勾选不必重发标签）
- `kind: "plan"` → `body` 是整份文档，首行必须是 `# 标题`（标题从这里取，不要再单独传）

## 指定项目

知识按项目分开。默认写当前工作区；也可以用：

- `directory`：项目绝对路径
- `projectId`：`list` 返回的项目 id

两者**只能给一个**（都能指到项目，同时给会被拒绝）。

## 覆盖保护（`expected`）

替换笔记或计划时，可以传 `expected` = 你**上次读到的原文**。如果这段文字已经被别人改过（通常是人在面板里编辑），调用会失败并提示重新 `list`——而不是默默覆盖掉别人的修改。

- 新建时不能传 `expected`（没有可比较的原文）
- todo 不支持（它只改自己那一两个字段）

## 约束

- **先 `list` 再写**：避免重复条目，也避免覆盖用户刚加的东西。
- **todo 与 todo 工具不是一回事**：`todo` 工具管理**当前这一轮**的任务进度（会话内，随会话结束消失）；本工具的 `todo` 是**跨会话长期待办**。要跟踪"这次任务做到哪了"用 `todo`，要记"以后还要做什么"用本工具。
- **计划是整份替换**：改计划先取全文（`show` 或直接读它给出的路径），改完整体写回，不要凭记忆重写（会丢内容）。
- **计划本质是 markdown 文件**：`list` 会给路径，长文档用你的文件工具读改，比整篇塞进工具结果更省。
- **别把过程写进笔记**：笔记是结论和约定，不是操作日志。
