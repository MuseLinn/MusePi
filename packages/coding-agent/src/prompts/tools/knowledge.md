# knowledge — 项目知识（笔记 / 待办 / 计划）

读写**当前项目**长期保留的知识，三条线：

| kind | 是什么 | 何时用 |
|---|---|---|
| `note` | 一段 Markdown 笔记 | 记下结论、约定、踩过的坑 |
| `todo` | 一条可勾选的待办 | 跨会话要跟进的事 |
| `plan` | 一整份 Markdown 计划文档 | 多步骤方案（开头必须是 `# 标题` 行） |

这三样和右侧「项目知识」面板是**同一份数据**：写进去用户立刻能看到，用户在面板里的改动你也读得到。

## 怎么用

```
knowledge { action, kind?, id?, body?, text?, done? }
```

| action | 必填 | 说明 |
|---|---|---|
| `list` | — | 一次列全：所有笔记、待办、计划 |
| `save` | `kind` + 内容 | 新建（不带 id）或替换（带 id） |
| `delete` | `kind` + `id` | 删除一条 |
| `show` | `kind: "plan"` + `id` | 取出计划全文（用户要读它时） |

`save` 的字段按 kind 取：

- `kind: "note"` → `body`（笔记正文）
- `kind: "todo"` → 新建给 `text`；改已有给 `id`，`done` 可单独发送（只勾选不必重发标签）
- `kind: "plan"` → `body` 是整份文档，首行必须是 `# 标题`（标题从这里取，不要再单独传）

## 约束

- **先 `list` 再写**：避免重复条目，也避免覆盖用户刚加的东西。
- **todo 与 todo 工具不是一回事**：`todo` 工具管理**当前这一轮**的任务进度（会话内，随会话结束消失）；本工具的 `todo` 是**跨会话长期待办**。要跟踪"这次任务做到哪了"用 `todo`，要记"以后还要做什么"用本工具。
- **计划是整份替换**：改计划先 `show` 取全文，改完整体写回，不要凭记忆重写（会丢内容）。
- **别把过程写进笔记**：笔记是结论和约定，不是操作日志。
