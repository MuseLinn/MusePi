Drives a real Chromium tab; full puppeteer access via JS. In the desktop app, tabs open in the built-in browser panel by default; a headless Chromium is only the fallback when no desktop app is attached or its built-in browser is disabled.

<instruction>
- Static content? `read` the URL. Browser only for rendered text, JS execution, auth, interactive actions, or visual inspection.
- `action:"status"` discovers browser availability and tabs without opening one. `activeTabId` is the agent control target; `visibleTabId` is the page the user is viewing. Never confuse them.
- `open` → `read` / `run` / `screenshot` — tabs survive calls and subagents, open once reuse.
- `action:"navigate"` opens an HTTP(S) URL in the current tab; `action:"search"` uses the configured search engine. `action:"back"`/`action:"forward"` move through real history, `action:"reload"` re-requests the page, `action:"stop"` sends CDP `Page.stopLoading`, and `action:"wait_load"` waits for `state:"committed"|"dom_ready"|"complete"` using current `document.readyState` (already-satisfied states return immediately).
- `action:"wait_for"` waits for an element `{kind:"element",locator:{role,name?,exact?},state:"visible"|"hidden"|"enabled"}`, text `{kind:"text",text,match?:"exact"|"contains",state:"present"|"absent"}`, or URL `{kind:"url",value,match:"exact"|"prefix"}`. `timeoutMs` defaults to 10000 (max 30000); `stableForMs` (0–5000) requires the condition to remain true and resets after a failed observation. Match and timeout both include `lastObserved`; timeout is an error result with evidence, so inspect it instead of retrying blindly.
- `action:"read"` returns rendered text blocks. `scope:"viewport"` is the default; use `scope:"document"` for loaded offscreen content. For one element subtree, use `scope:"element"` with the `snapshotId` and `ref` from the same `elements` snapshot; sibling text is excluded and the usual pagination applies. Reading never scrolls or loads more content. `maxChars` defaults to 12000 (2048–24000). Continue with `cursor` set to the returned `nextCursor` only; do not invent offsets. Text block ids are not element refs.
- Use `tab.observe()` for legacy observation or `action:"elements"` for explicit element snapshots. `elements` returns a `snapshotId` and `eN` refs with role/name/state. Defaults: viewport, 100 elements, 8000 chars. Filter with `role`/`filterText`; continue with the same `snapshotId` and returned `nextCursor`.
- `action:"visual"` returns a screenshot and its coordinate snapshot. Use `click`/`hover` with `snapshotId` plus `x`/`y`, or `scroll`/`drag` with that visual snapshot. Coordinates are pixels in the returned image and are mapped to the captured CSS viewport.
- `action:"click_if_interactive"` clicks only when the requested point itself is interactive. If it is not, nearby candidates are returned and are never clicked automatically; inspect them and choose a fresh exact point instead. Candidate coordinates and distances use returned screenshot pixels. `radius` defaults to 48 and is bounded to 8–128. `action:"visual_type"` clicks a visual point and types `text`, replacing existing text when `replace:true`; `press` accepts optional `x`/`y` to focus a visual point before the key chord.
- `action:"visual_crop"` reads a region from the original image behind a visual snapshot. Supply `snapshotId` and `region:{x,y,width,height}` in returned screenshot pixels. The result has `sourceSnapshotId`, region, original capture time and cropped image, but no new clickable snapshot. For local crop coordinates, `sourceX=region.x+localX*region.width/width` (same for Y).
- `action:"drag_path"` presses at `points[0]`, moves continuously through every point and releases at the last. Use 2–500 points in returned screenshot pixels for drawing, signatures or curved sliders. Optional `button`, `durationMs` (0–20000 total), and `modifiers` such as `["Shift"]`. Repeat the first point at the end to close a shape.
- Explicit actions: `click`, `double_click`, `right_click`, `click_if_interactive`, `visual_type`, `fill`, `type`, `press`, `hover`, `scroll`, `drag`, `drag_path`, `select_option`, `set_checked`, `scroll_into_view`. Element actions require a ref from the same `elements` snapshot; coordinate actions require a visual snapshot. Snapshots expire after 60 seconds and are bound to their named tab. Stale/invalid refs never click blindly — capture a fresh snapshot after navigation or re-render.
- Pick the action by intent: `click_if_interactive` when a visual point may miss and nearby candidates would help; `scroll_into_view` before acting on an element outside the viewport; `hover` to reveal hover-only menus; `right_click` for context menus; `double_click` for list/tree rows that open on activation. Each of these can change the page, so re-read the state you depend on afterwards.
- Use `action:"screenshot"` for appearance. Do not use screenshots as a substitute for text or element reads.
- `action:"device_profiles"` lists device presets. `action:"set_device"` applies `device:{enabled:true,profileId,orientation,scaleMode,...}` or disables with `device:{enabled:false}`. Responsive requires `width`/`height` and uses mobile identity and touch; presets forbid explicit dimensions. `scaleMode:"fixed"` requires `scale` (0.01–1); `"fit"` forbids it. Display scale is separate from CSS viewport and page zoom. Re-observe after device changes because the page may reload.
- `action:"history"` and `action:"downloads"` read retained records across conversations in the current managed application profile, newest first (up to 200 history entries or 100 downloads). Download records include status and optional `savePath`; query again for progress. Times are Unix milliseconds and sizes are bytes; `totalBytes=0` may mean unknown. A recorded savePath does not guarantee the file still exists. These actions require the managed Electron browser profile and fail explicitly otherwise.
- `activate` selects an existing/adopted control target without revealing it. `action:"activate_panel"` reveals the existing managed panel without creating or switching a tab. `switch` also reveals the real target. `release` detaches Agent control without closing the page; it is not `close`.
- JavaScript dialogs pause page operations. Inspect `pendingDialogs` in run results or use `action:"dialog"` to read the current alert/confirm/prompt. Use `action:"dialog_respond"` with `accept:true` to accept or `accept:false` to dismiss; pass `text` for a prompt. `handledDialogs` records the outcome and whether the Agent, user, or auto-policy answered. Re-read the page after responding.
- `run` scope: `page`, `browser`, `tab`, `display`, `assert`, `wait` available. `wait(fn)` polls until truthy — use instead of polling inside `tab.evaluate`.

- `tab` helpers for interactions and observations not covered by structured actions (drop to raw puppeteer `page` for anything uncovered):
  Element handles: `tab.ref("e5")` / `tab.id(n)` return a handle you call methods on directly — `(await tab.id(n)).click()`. Handles are NOT selectors: `tab.click`/`type`/`fill`/`waitFor*` take STRING selectors only. Snapshot refs work in any selector slot: `tab.click("e5")` ≡ `tab.click("aria-ref=e5")`.
  Simple: `tab.goto`, `tab.click`, `tab.type`, `tab.fill`, `tab.press`, `tab.scroll`, `tab.scrollIntoView`, `tab.drag`, `tab.uploadFile`, `tab.select`, `tab.screenshot`, `tab.extract`, `tab.evaluate`.
  Screenshots: `tab.screenshot({ selector?, fullPage?, silent? })` saves to `browser.screenshotDir`, or OS temp when unset, then returns the path. It NEVER accepts a path.
  Waits: `tab.waitFor`, `tab.waitForSelector`, `tab.waitForUrl`, `tab.waitForResponse`, `tab.waitForNavigation`.
  Snapshots: `tab.observe()` → accessibility tree; `tab.ariaSnapshot()` → ARIA YAML with `[ref=eN]`.

  Gotchas:
  - `tab.fill` NEVER works for `<select>` — use `tab.select`.
  - `tab.waitForNavigation` must start BEFORE the trigger click.
  - Navigation and re-renders (virtualized lists, SPA updates) invalidate ids/refs — re-observe or re-snapshot, then act in the same cell.
  - Stalled actions fail fast with named error, never whole-cell timeout.
  - Raw request interception is run-scoped: run end removes `request` handlers, disables interception, releases held requests.

- `app.path` → NEVER tamper with a real desktop app (no stealth patches).
- `app.relay: true` → drive the user's own Chrome tabs via the musepi browser relay (auto-started; needs the MusePi Browser Relay extension installed). `app.target` picks a tab by URL/title substring; without it the visible tab is adopted without stealing focus.
{{#if managedBrowser}}- **Managed browser channel**: your tabs open in a dedicated agent tab of the app's built-in browser (selected when created). The user watches every page and navigation in the side panel, can interact with or take over the tab at any time, and the pages share the user's login state. Only an explicit `app.target` takes over a tab the user already has open — matched as a case-insensitive url/title substring (the lookup neither focuses nor duplicates it), and an unmatched target is an error; without a target you get the dedicated agent tab. Never assume a private/headless browser here, and never look for these pages with the `computer` tool: an embedded page is not an OS window.{{/if}}
- Selectors: CSS + puppeteer `aria/…`, `text/…`, `xpath/…`, `pierce/…`. Playwright-only pseudos (`:has-text()`, `:visible`) are REJECTED.
</instruction>
